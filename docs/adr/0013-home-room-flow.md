# ADR-0013: 홈의 두 입력 경로에서 같은 방 화면을 연다

- 상태: proposed (#245, 홈 흐름 운영자 승인)
- 관련 결정: [ADR-0006](0006-favor-draw.md), [ADR-0011](0011-host-entered-draw-room.md)

홈에서 '각자 입력'은 자기 출발역으로 방을 만들고, '방장이 입력'은 친구의 칸도 채운 뒤 방을 만듭니다. 두 방식 모두 `/r`에서
추천과 공유, 뽑기, 만날 역 정하기를 이어 갑니다. 기존 `/result`와 `/s`는 계속 읽을 수 있고, 다시 입력·SEO 링크는 홈의 초안만
채웁니다. 저장은 사용자가 범위 안내를 읽고 방 만들기를 제출할 때 일어납니다.

- 새 `POST /v1/filled-rooms`는 일반 추천부터 여는 잠긴 방에 방장과 대신 입력한 칸을 원자적으로 저장합니다. `/draw-rooms`는
  기존 클라이언트용으로 계속 뽑기 방을 만듭니다. 이전 서버는 새 경로를 404/405로 거절합니다. 웹은 기존 생성 경로로 재전송하지 않습니다.
- 명단 순서와 내 칸 표시, `enteredByHost`의 공용 미리보기 가림, 복구·저장 실패 시 방 삭제는 ADR-0011을 이어 씁니다. 두 생성
  경로의 복구 키는 서로 다른 방을 되찾습니다. 응답을 잃은 뒤 이전 서버에서 새 경로를 거절해도 기기의 복구 키를 보관합니다.
- [ADR-0012](0012-retire-hidden-origins-in-steps.md)의 숨김 거절은 세 생성 경로 모두에서 멱등 재생과 복구보다 먼저 적용합니다. 숨긴
  행이 복원된 방은 방·결과·공용 미리보기를 가리고 그 방의 토큰에 따라 지우기만 허용합니다. 채운 방을 복구할 때도 방의 내용 없이 생성
  응답을 돌려줍니다. 이미 지워진 참여자 토큰을 받으면 웹은 방장 토큰으로 다시 확인하고 다른 탭의 방장 기록을 보존합니다.
- 방장의 `POST /rooms/{roomId}/favor-draw/start`는 방을 새로 만들지 않습니다. 방 행의 공유 번호를 잠금 안에서 비교한 뒤 새 뽑기
  세대를 시작합니다. 이미 켜져 있으면 아무것도 쓰지 않습니다. 실제 뽑기는 기존 세대·회차·다시 뽑기 규칙을 씁니다. 켜기 전에는
  기존 추천 기준으로, 켜고 첫 뽑기 전에는 공평하게 결과를 보여 줍니다. 읽기와 그 밖의 추천 기준은 계속 선택할 수 있습니다.
- 요일 유형과 시간대는 ADR-0011처럼 방의 약속일·시간대로 옮깁니다. 주말과 공휴일은 가장 가까운 해당 날짜와 그다음 날 만료를
  저장 전에 안내합니다. 기존 결과에서 다시 입력할 때의 추천 기준과 배려 대상도 입력 순서로 복원합니다.

서버 먼저 배포합니다. 웹이 먼저 나가거나 서버만 직전 판(#244)으로 돌아가면 그 서버는 새 생성과 사다리 켜기를 거절합니다. 이미 만든
방의 읽기에는 직전 판의 공개 범위가 적용됩니다. #229의 대리입력 가림이 없는 서버로 되돌리지 않는 제약은 ADR-0011을 따릅니다. 처리방침
직전 판은 #244의 11월 27일 개정판입니다. 실제 병합일에 웹 배포일(KST)과 처리방침 시행일, 안내 이월을 확인합니다. 기존 통계 항목과
동의 버전을 사용합니다.
