# ADR-0008 반반역의 교통 권역

- 상태: proposed (#180). 운영자는 2026-11-25에 단계적 진행, 화면 이름 ‘부산권’, 내부 키 `busan`, 부전 두 코드 보존과 외부 도보를 정했다. 발행은 운영자의 별도 승인 후 진행한다.
- 근거: [부산 도시철도 조사 §5](../research/busan.md#5-설계-영향과-작업량)

## 결정

- 권역 그래프와 `od.bin`, `rg.bin`, `lt.bin`은 전국 한 벌로 발행한다. 후보와 역 축을 확장하고 OD의 다른 권역 칸은 도달 불가 표식인 시간 `0xFFFF`와 환승 `0xFF`를 함께 쓴다. `stations.json`의 각 역에 `region`을 두고 기존 도달 불가 후보 제외 규칙과 공평 순위(minimax)를 그대로 쓴다. 새 그래프는 rg 형식 2를 쓰고 `regional/manifest.v5.json` 및 `regional/versions/<dataVersion>/…`에 둔다. 기존 포인터와 파일을 보존해 기존 서버가 권역 파일을 읽지 않게 한다. 전국 파일에서 수도권 축에 투영한 기본·구분별 OD의 시간·환승 값 및 rg로 재계산한 수도권 OD가 기존 값과 같고, 수도권 막차 값과 SEO 상위 3개가 일치해야 발행한다. [데이터 형식 §11](../../contracts/data-format.md#11-rgbin--사람별-경로의-노선-그래프-120)
- 역의 권역은 국토교통부 도시철도 전체노선(M1)의 ‘권역’에서 가져온다. 역 조인이 빠지거나 그래프 연결 성분이 권역과 어긋나면 발행을 막는다. 부산 권역에는 동해선 울산 구간(서생~태화강)과 김해가 들어간다. 내부 식별자는 M1 원본값과 별개로 안정적인 영문 키를 쓴다(부산은 `busan`).
- 화면 이름은 **부산권**이다. ‘수도권’과 짝이 맞고, 부산시 광역도시계획에서 쓰는 광역 명칭으로, 서비스에서는 울산·김해 연결을 아우른다. ‘부산권 전철 N개 노선을 계산해요’로 안내하고, 펼치면 지원하는 노선 목록을 보여 준다(#170). [부산시 광역도시계획](https://www.busan.go.kr/depart/agora0702)
- 한 방과 한 추천 계산에는 한 권역만 허용한다. 웹은 첫 출발역의 권역이 정해진 뒤 다른 권역의 역 선택을 막는다. 서버는 직접 추천, 공유 링크, 방 생성·참여·출발역 수정과 추천·미리보기 진입점에서 권역을 검증한다. 권역이 섞이면 역이나 참가자 식별자 없이 `REGION_MISMATCH`를 반환한다. 숨긴 참가자가 남아 있는 옛 방은 기존 수도권 방 규칙을 따르고 공개 응답에 숨긴 출발역의 권역을 추가하지 않는다.
- 대구·대전·광주도 같은 규칙을 쓸 수 있게 원천 설정, 영수증, 신선도, 도달률과 비교 게이트를 권역 단위로 둔다. 부산 막차는 현행 운영사 공식표와 노선·요일·행선지 대조를 통과한 칸에만 표시한다. 환승 경로에는 출처로 검증된 환승만 쓰며, 미확인 범위는 끈다. 원천 기준일과 운영사 개정 공지를 기준으로 판단하며, 한 권역의 신선도나 비활성화 상태가 다른 권역에 영향을 주지 않도록 한다.

## 트레이드오프와 적용 범위

전국 한 벌은 지역별 파일보다 빈 칸이 많다. 부산을 더하면 조사 기준 약 8.7만 칸에서 약 12.2만 칸으로 늘지만, 구분별 행렬과 막차를 합쳐도 수 MB 규모로 예상한다. 데이터 크기나 독립 발행의 필요성이 커지면 지역별 파일 분리를 다시 검토한다.

첫 단계에는 이 결정의 기록과 원천 수집·검증을 진행한다. 그래프와 데이터 발행, 서버 계약, 화면, 막차는 후속 단계에서 적용한다.

부전 1호선(`hsd`)과 동해선(`1bp`)은 역 코드 둘을 보존하고 개찰구 밖 외부 도보 간선으로 양방향 연결한다. 평시 보행 계획값은 480초다. 실측과 보행시간 상한은 추가 검증이 필요하다. 첫 승차 전과 마지막 하차 후에는 걸은 시간만 더한다. [철도산업정보센터 이용자 여행 글, 2017-01-10](https://www.kric.go.kr/jsp/board/portal/sub05/res/themeEssayDetail.jsp?board_seq=2479)
