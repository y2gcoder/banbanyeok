# ADR-0001: 법정 고지 사항이 실질적으로 바뀔 때만 CONSENT_VERSION을 올린다

- 상태: 채택 (2026-11-21, #114·#116)
- 바꾼 결정: `consent-text.ts` 머리 주석과 `docs/legal/privacy-policy-change.md`의 "사용자에게 보이는 동의 문구가 바뀌면 올린다"(P7·W1에서 정함)

## 맥락

통계 동의 배너의 첫인상이 나빴다. 지인이 "미국 PostHog, Inc.로 통계 전송에 동의해요 (선택)"를 보고 "아니요?"라고 했다. #114는 알릴 사항을
빼지 않고 배치·순서·톤만 바꾼다. 그런데 기존 규칙대로라면 문구를 고칠 때마다 `CONSENT_VERSION`을 올려야 하고, 올리면 이미 동의한 사람의
기록과 `ph_*` 식별자를 지운 뒤 다시 묻는다. 이용자가 아직 적어 한 번 동의해 준 사람을 다시 묻는 비용이 크다.

#116 검토에서 두 가지가 더 나왔다. 처음 쓴 기준("항목·목적·이전받는 자·국가·보유 기간")은 법이 알리라고 정한 사항을 다 담지 못했다
(예: 이용할 때마다 보내던 것을 월별 일괄 전송으로 바꾸면 열거한 항목은 그대로인데 고지 사항은 바뀐다). 또 배너 한 화면에는 이전받는 자의
연락처와 항목 일부(브라우저·기기 정보, 화면 크기, 방문 주소, 접속 IP)가 없었다.

## 결정

`CONSENT_VERSION`은 **개인정보 보호법 제15조 제2항과 제28조의8 제2·3항의 고지 사항 중 하나라도 실질적으로 바뀌면** 올리고 다시 묻는다:
수집·이전하는 항목, 이용 목적, 보유 기간, 이전받는 자와 그 연락처, 이전되는 국가, 이전 시기와 방법, 거부할 권리·거부 방법·절차와
거부했을 때의 불이익(효과). 두 항목을 나눠 받는 방식이 바뀌어도 올린다.

올리지 않는 것: 같은 내용을 다르게 쓰기, 배치·순서 바꾸기, 처리방침에 이미 있던 사실을 배너에 옮겨 적기, **고지가 보이는 층만 바꾸기**
(예: 요약에 있던 것을 '자세히'로 옮기거나, 처리방침에만 있던 것을 배너의 '자세히'에 더하기). 처리방침 15항("이용 통계의 항목이나 목적이
바뀌면 … 동의를 다시 받습니다")보다 넓은 기준이다.

### 이번 결정(#116): v4 그대로

#116은 배너 요약을 그대로 두고, 법정 고지 사항 전부(연락처 privacy@posthog.com, 빠졌던 항목, 수집·이전 모두 1년)를 배너의 '자세히 보기'
(같은 자리에서 펼침)와 /privacy 통계 설정에 넣는다. 사항 자체는 하나도 바뀌지 않았다. v4 동의를 받을 때도 같은 사항이 처리방침 2·4·7항에
있었고 배너의 링크 한 번으로 닿았다. 표시 위치·층만 바뀌었으므로 올리지 않는다(사용자 확인 필요: 병합 때 최종 확인).

검토자는 "완전한 고지로 v4 동의를 받았다는 근거가 없다면 다시 물어야 한다"고 봤다. 다시 묻지 않는 쪽을 고른 이유는 위와 같고, 이 판단이
틀렸다고 보면 v5로 올리는 것은 한 줄 변경이다(`consent.ts`의 `CONSENT_VERSION`, 낡은 기록과 식별자는 자동으로 지워진다).

## 근거와 트레이드오프

- 개인정보 보호법이 다시 동의를 요구하는 것은 동의받은 사항이 바뀔 때다. 같은 사항을 더 알기 쉽게 쓰거나 보이는 자리를 바꾼 것은 이미 받은
  동의의 범위 안이다. 반대로 열거 목록이 법정 사항보다 좁으면 바뀐 사항을 놓칠 수 있어, 기준을 법정 사항 전체로 둔다.
- 대가: 같은 버전(v4)에 화면 문구가 둘 이상 있게 된다. 어느 날 어떤 문구였는지는 `consent-text.ts`의 git 기록과 PR 본문(전후 표)으로 본다.
  `docs/setup/p7-notes.md`의 대조표는 버전을 올린 경우의 기록으로 남는다.
- 애매하면 올린다(다시 묻는 편이 안전하다).
