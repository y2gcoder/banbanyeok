# 반반역 — 공통 브리프 (모든 작업자 필독)

## 한 줄
"우리 어디서 만나야 덜 억울할까?" — 지리적 중간이 아니라 **대중교통 실제 이동 부담**으로 만날 역을 추천한다.

## 대표 기능
1. 실제 이동시간 기준 추천: 후보역마다 각자 소요시간 / 환승 횟수 / 추천 이유를 보여준다. 불투명한 "공평 점수"만 보여주지 않는다.
2. 만남 기준 전환
   - 공평하게: 가장 오래 걸리는 사람의 시간을 줄인다 (minimax). 시간 차이는 동점일 때 순위를 가르는 데 쓴다.
     (단순 "차이 최소화"는 둘 다 70분인 역을 30/40분 역보다 위에 올리는 문제가 있어 쓰지 않는다.)
   - 빨리 만나기: 총 이동시간을 줄인다.
   - 오늘은 네 쪽으로: 특정 사람의 부담을 줄인다.
3. 공유: 설치 없이 열리는 링크로 각자 이동 부담을 확인한다. 결정한 역은 지도 앱으로 연결한다.

## 1차 범위로 정한 것
- 지역: 수도권 지하철만 (버스는 나중에)
- 인원: 2~4명 (알고리즘은 처음부터 N명 기준)
- 소요시간: 요청마다 외부 API를 부르지 않고 **역 간 소요시간을 미리 계산**해 둔다 (수도권 역 약 600~700개)
- 후보역: 전체 역이 아니라 **실제로 약속을 잡는 역** 50~100개로 미리 추린다
- 공유는 링크 하나로 각자 시간을 보는 데까지. 투표와 출발지 숨기기는 나중에
- 차별점 후보: **귀갓길 막차** 반영 ("이 역에서 만나면 A는 23:40, B는 00:15까지 가능")

## 작업 규칙
- 작업 폴더: 저장소 루트(`banbanyeok/`)
- 여러 작업자가 같은 폴더에서 동시에 일한다. **자기 담당 파일만** 만들거나 고친다.
- 문서는 한국어로 쓴다. 사실을 주장할 때는 출처 URL과 확인한 날짜를 적고, 확인한 사실과 추정을 구분한다.
- 문서 맨 위에 "결론 / 권고" 섹션을 먼저 쓴다 (코디네이터가 이 부분을 종합한다).
- 열린 질문은 문서 맨 끝 "결정 필요" 섹션에 모은다.
