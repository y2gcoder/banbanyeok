# 수도권 지하철 데이터 소스 조사

## 결론 / 권고

**권고 조합: 공공 정적 데이터와 공공 시간표로 자체 그래프를 구축하고 역→후보역 소요시간을 미리 계산한다. 수도권 전역의 최신 막차까지 확보했다고 볼 수는 없다.** 확인일은 모든 항목 **2026-11-12 (JST)** 이다. 아래에서 ‘확인’은 공식 문서 또는 실제 응답으로 확인한 사실, ‘제안’은 구현·운영 판단이다.

| 용도 | 1차 선택 | 보완 / 공백 |
|---|---|---|
| 역·노선 목록과 좌표 | 국가철도공단 도시광역철도 역사정보 XLSX [S1] | 서울 역코드 API [S2]와 매핑. XLSX에 GTX-A라는 노선명은 없고 기관마다 기준일이 달라 최신 전역 목록을 보장하지 않는다. 신설역·개통구간은 별도 검증 필요 |
| 인접역 운행시간 | 서울교통공사 역간거리 CSV [S3] + 서울 시간표 [S5] | CSV는 1~8호선 일부 운영범위. 수도권 나머지는 TAGO 시간표 [S6]를 우선 수집·검증하고, 공공 최단경로 API [S7]의 구간정보로 보완·대조. KTDB GTFS [S8]는 자료 신청 및 이용범위 확인 후 일괄 초기 구축 후보 |

**판정(제안): 일반적인 이동 부담 추천 MVP는 가능하다.** 다만 ‘전체 수도권 완성’의 조건은 노선·방향별 인접 간선, 환승 간선의 누락률을 실제 수집 후 확인하는 것이다. 이번 조사는 전체 수집 작업이 아니라 소스 선정과 표본 검증이다. **막차는 별도 출시 조건**으로 잡고, 데이터가 불완전한 경로는 ‘확인 불가’로 보여주는 것이 맞다.

### 즉시 드러난 데이터 공백

- **최신성:** S1의 포털 설명은 2024년 파일/1,073행인데 실제 다운로드는 1,099개 데이터행이다. 행 기준일도 2022~2026년 혼합이다. ‘최신 파일 다운로드’가 ‘전체 최신’이라는 뜻은 아니다.
- **코드 연결:** 운영기관 역번호, 서울 내부 `STATION_CD`, 외부 `FR_CODE`, TAGO 역 ID, GTFS `stop_id`는 서로 다르다. 역명만으로 결합하지 말고 기관·노선·좌표를 함께 사용한다.
- **운행 패턴:** 급행·완행·지선·직통·중간 종착의 차이를 보존해야 한다. 수인선/분당선, 경부선/경인선처럼 원본 노선 구분도 앱의 노선명과 다를 수 있다.
- **환승:** 이번에 받은 S4는 140행으로 수도권 모든 방향별 환승을 보장하지 않는다. 환승 도보와 열차 대기를 분리해야 한다.
- **막차:** 현재 모든 수도권 노선의 토요일·일요일/공휴일 전체 시간표를 인증 없이 일괄 받는 소스는 확보하지 못했다. TAGO 키 발급 뒤 우선 커버리지를 확인하고, 누락 운영사에는 재사용 가능한 기계 판독 시간표 제공을 문의한다.
- **권리:** KTDB 파일럿의 상업 서비스·가공결과 배포 허용 범위는 신청 단계 확인이 남았다. 상용 경로 API를 무료 쿼터만 보고 영구 행렬 원천으로 채택하지 않는다.

### 수도권 전체 커버리지 해석

KTDB 자료는 표준 GTFS와 동일한 파일명·ID 결합이 된다고 아직 확인하지 못했다. 수령 후 정차지 좌표, 운행회차별 정차 순서, 인접 정차지 출발→도착 시각 차이, 환승 최소시간을 추출할 수 있는지 검사한다. 환승정보가 있다는 공지만으로 도보시간 필드가 모두 채워졌다고 간주하지 않는다.

S1 실제 파일에는 서울교통공사 277행, 한국철도공사 334행, 공항철도 14행, 신분당선 16행, 인천교통공사 71행 등이 들어 있다. 코레일 광역의 경의중앙·경춘·경강·서해·수인·분당 및 1호선 계열, 9호선, 김포·의정부·용인·우이신설·신림 관련 노선명이 확인된다. **이 숫자는 노선별 역사 레코드 수이며 물리적으로 다른 역의 수가 아니다.** 전국 자료에는 부산·대구·광주·대전 및 자기부상철도도 섞여 있어 노선·운영범위·운행 여부로 필터해야 한다. 실제 노선명 전체와 원본 해시는 `data/samples/kric-inspection.json` 참조.

GTX-A 노선명은 이번 XLSX에서 찾지 못했다. 코레일이나 서울의 ‘수도권 데이터’라는 이름만으로 공항철도·신분당선·인천·신규 연장까지 완비됐다고 판단하면 안 된다. S7 표본이 수인분당선을 경유한 것은 확인했지만, 나머지 운영사 포함 범위는 역별 요청으로 검증해야 한다.

운영사 웹 시간표는 공백 보완 후보이나 공개 열람과 상업적 일괄 재사용 허락은 구별한다. [신분당선 소요시각표](https://shinbundang.co.kr/index.jsp?open_main=1&open_sub1=4&open_sub2=2&pageID=%2Fdxline%2Fdxline3_2.jsp)는 구간별 분·초 시간표를 공식 게시한다(HTML, 개정 시 변경, 파일 미수신, 재사용 라이선스 미확정). 나머지 운영사 시간표를 임의 크롤링하는 대신 S6 커버리지 확인 뒤 필요한 기관에만 문의하는 편이 비용이 작다. TAGO [열차정보](https://www.data.go.kr/data/15098552/openapi.do)는 지하철정보와 별도 서비스이므로 일반열차 시간표를 수도권 전철 시간표로 혼동하지 않는다.

## 2. 실제 표본으로 확인한 필드와 함정

### 역 목록·좌표

- S1 XLSX의 15열 헤더와 20개 운영기관 대표행을 `kric-stations.sample.csv`에 UTF-8로 추출했다. 빈 셀은 셀 주소(A~O)에 맞추어 유지했다. 원본 대용량 파일은 저장하지 않았다.
- 예: 신사/신분당선/D004, 위도 `37.516125263312901`, 경도 `127.019760916726`. 역번호는 숫자로 변환하면 안 된다.
- 날짜는 ISO 문자열, `20240812`, Excel 일련번호 `46191`(1900 날짜체계로 2026-06-18), `1900-01-00`, 빈 값이 혼재한다. 인입 시 날짜 정규화와 오류 격리가 필요하다.
- S2 sample 응답은 수원·오목천·인하대 등 코레일 역도 포함하고 `list_total_count=799`지만 좌표는 없다. 표본 순서가 노선 순서라고 가정하지 않는다.

### 운행시간·환승시간

S3 실제 헤더는 설명의 ‘운행시간(분)’과 달리 **`소요시간`이며 값은 `02:00` 형태**다. 서울역 `00:00`, 다음 시청 `02:00`, 종각 `02:00`가 이어진다. 앞 역→해당 행 역의 간선이라는 해석이 자연스럽지만(추정), 지선·순환·방향을 별도 노선 순서와 대조한 뒤 확정해야 한다. 이 파일만 정렬하여 전체 그래프를 만들면 안 된다. 승강장 정차시간과 최초 대기시간도 별도로 고려한다.

S4의 서울역 1→4호선은 159m/02:13, 1→공항철도는 309m/04:18이다. 공식 설명은 보행속도 1.2m/s로 거리/속도를 계산한 참고치라고 밝힌다. 열차 대기시간·혼잡·엘리베이터 이동은 포함된 것으로 보지 않는다. 반대 방향과 방향별 승강장 위치를 같은 값으로 가정하지 않는다.

S7 표본은 문서의 일반 `list_total_count/row` 봉투와 달리 실제 **`header.resultCode="00"` + `body.paths[]`**다. `totalReqHr=1800`, 환승 횟수 2, 개별 구간에 `reqHr`, `wtngHr`, 출발/도착시각이 있다. `paths`의 `reqHr` 합은 1316, `wtngHr` 합은 304로 총 1800과 일치하지 않는다. 첫 구간 답십리→마장의 응답 시각도 10:06:00→10:06:30이다. **총시간과 구간시간의 의미·초 단위·대기 중복 계산 여부를 담당기관에 확인하고 다른 시간표와 대조하기 전, 이 값을 무비판적으로 자체 간선으로 복제하지 않는다.** 이 API는 초기 대조·누락 발견에 특히 유용하다.

### 시간표·막차

S5 표본은 지축/평일/상행 120건 중 첫 5건이며, 첫 응답은 열차 3012의 도착 `05:59:00`, 출발 `05:59:30`, 행선 대화다. 열차번호가 `3024K`처럼 문자도 포함한다. 샘플 5건으로 막차를 확인했다고 할 수 없다.

페이지 본문은 운영 1~9호선을, FAQ는 1~8호선을 안내하여 범위 표현이 서로 다르다. 그러므로 ‘서울 API니까 코레일 포함 전 노선 시간표가 있다’고 전제하지 않는다. 실제 역코드별 빈 응답과 운영사별 대표역을 확인해야 한다.

**구현 제안:** 같은 운행일·열차번호·방향·패턴으로 인접역의 출발/도착을 연결해 운행시간을 구한다. 날짜가 넘어가는 00시대와 24시 이상 표기는 서비스일 기준 초로 정규화한다. 귀가 가능 출발 시각은 목적지에서 역방향으로 시간표를 탐색하고, 환승 도보+여유시간을 만족하는 연결만 선택한다. 행선지별 ‘막차 시각’만 빼서 계산하면 중간 종착·환승 단절을 놓친다.

파일 다운로드의 `seq`는 페이지 최신 목록에서 확인한 값이며 고정 API 계약이 아니다. S4의 잘못된 seq 요청은 HTTP 200이어도 HTML 오류를 반환했다. 수집기는 상태코드뿐 아니라 Content-Type/본문·스키마를 검사해야 한다. 서울 상세 페이지도 간헐적으로 ‘서비스 지연(103)’ HTML을 반환했다. `https://openapi.seoul.go.kr:8088/...`는 이 실행에서 TLS 오류였고 공식 HTTP URL은 성공했으므로, 서버 배치에서 호출하고 실제 지원 HTTPS 주소는 별도 확인한다.

인증 절차:

1. **서울 열린데이터광장:** 회원가입/로그인→Open API 인증키 신청→활용 서비스 등록. `sample`은 1~5건 제한이므로 전체 시간표·역 목록에는 본인 키가 필요하다. 역×요일×방향×페이지별 호출계획과 배치 주기를 정한다.
2. **TAGO:** 공공데이터포털 로그인→S6 활용신청(개발단계 자동승인)→발급 ServiceKey로 명세의 역 검색→역 ID로 요일·방향별 시간표 조회. 운영 트래픽 증설은 활용사례 등록 후 신청 가능. 키를 문서/공유 링크에 넣지 않는다.
3. **KTDB:** 정보공개→자료신청→교통분석자료→교통망 GIS DB→대중교통→대중교통 GTFS→목적·소속 입력 후 자료 수령. 신청서에 ‘상업 서비스의 그래프·역간 행렬 생성 및 사용자 결과 제공’을 구체적으로 적고 재배포 조건을 확인한다.
4. **외부 API:** ODsay는 회원·앱·서버 IP 등 플랫폼 등록 후 key, TMAP은 SK Open API 회원·앱 생성·상품 신청 후 appKey, 카카오는 앱 생성·카카오맵 활성화·REST API 키 설정. 계정 생성·유료 상품 신청은 이번 조사 범위에서 실행하지 않았다.

## 5. 사전계산 설계에 주는 제약 (제안)

- 그래프 노드는 물리역 하나가 아니라 **역×노선/승강장 그룹**으로 두고, 열차 운행 간선과 도보 환승 간선을 분리한다. 동일 명칭을 병합해 환승 0분을 만들지 않는다.
- 인접 간선의 시간은 운행시간과 정차를 구별해 초 단위로 보존한다. 평시 대표시간·환승횟수·경로를 먼저 계산하고, 대기시간을 포함한 예상치임을 사용자에게 명확히 표시한다.
- 일반 추천은 전체 역→후보역 50~100개 행렬로 충분하다. 후보역별 역방향 탐색으로 계산하면 된다. 공평 모드는 가장 큰 이동시간을 최소화하고, 시간차는 동률 해소에 쓴다.
- 막차를 제공하려면 별도로 운행일별 시간표와 도달 가능한 최종 출발 시각을 계산한다. 정적 행렬의 소요시간을 막차에서 빼는 방법은 쓰지 않는다.
- `source_url`, `fetched_at`, `effective_date`, `license`, `estimated`, `service_day`, 운행 패턴을 보존한다. 버전별 행렬 재생성과 누락 노선 차단이 가능해야 한다.
- 도입 전 검증 표본은 서울만 고르지 말고 경의중앙·공항철도·신분당·인천·경전철·GTX와 장거리 환승을 포함한다. 전체 인접 간선 수/누락 수, 방향별 환승 수, 3개 요일형 시간표의 빈 역 수를 보고 출시 범위를 확정한다.

## 결정 필요

1. MVP를 ‘수도권 일반 이동시간 추정’으로 먼저 출시하고, 막차는 데이터가 검증된 경로부터 한정 제공할 것인가? **권고: 그렇다.**
2. S6 인증키 발급과 실제 전역 커버리지 확인을 누가 수행할 것인가? 특히 코레일·공항철도·신분당·인천 및 신규 연장 확인이 다음 작업이다.
3. S7의 `reqHr`, `wtngHr`, 총시간 불일치의 의미와 지원 노선·배치 호출 한도를 제공기관에 확인할 것인가? **권고: 자체 간선 보완에 쓰기 전에 확인한다.**
4. KTDB에 상업 서비스 사용·가공 행렬 제공 범위로 자료를 신청할 것인가? 허용되더라도 2025 평일 하루 자료를 최신·주말 막차의 원본으로 쓰지는 않는다.
5. GTX-A·공항 직통·ITX 등 추가운임/별도 승차권 열차와 운행 중단 노선을 ‘수도권 지하철’ 범위에 포함할 것인가? 확정 후 노선 화이트리스트와 데이터 누락 기준을 정한다.
