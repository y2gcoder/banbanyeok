## 결론 / 권고

### 한 줄 요약
"실제 이동시간 기준 중간역 추천"은 이미 흔한 기능이다. 2026년에만 개인 개발자가 만든 앱과 웹이 최소 6개 나왔다. 반면 사용자가 실제로 쓴 앱은 위밋플레이스(평가 413개) 하나뿐이다. 이 앱은 2022-02 이후 업데이트가 없고, 2025-07 리뷰에는 "작동하지 않는다"는 보고가 이어진다. **시장에 자리를 잡은 앱은 없다. 다만 기능만으로 차별화할 여지는 좁다.** 반반역이 이기려면 기능 목록보다 **"표시한 시간이 맞고, 왜 이 역인지 한눈에 납득된다"**는 신뢰에서 앞서야 한다.

### 브리프의 차별점 후보 검증

| 후보 | 판정 | 근거 |
|---|---|---|
| 투명한 시간 표시 (각자 소요시간) | **차별점 아님 (기본 기능)** | 우리지금만나, 더치, 만나요, 어디서 볼까?, 위밋플레이스 모두 사람별 시간을 보여준다 [확인]. 다만 **환승 횟수와 추천 이유 문구까지 함께 보여주는 곳은 확인하지 못했다**. 우리지금만나는 README에 "환승 횟수와 노선 안내는 없습니다"라고 적어 두었다 [확인]. |
| 공평 기준 = 최장 시간 최소화(minimax) | **차별점 아님** | 우리지금만나(minimax, 동점이면 합계 기준), 중간에서 보자, 어디서 볼까?, 중간어디가 같은 방식이다 [확인]. |
| 기준 전환 (공평/빨리/네 쪽으로) | **절반만 차별점** | "공평/빨리" 전환은 만나역(이동시간 균형·이동거리 균형·빠른 만남)과 쎈터로(환승 최소화·귀가 시간 최소화)에 이미 있다 [확인]. **"오늘은 네 쪽으로"(특정인 배려)는 확인한 서비스 중 아무 데도 없다.** 반면 직접 요청한 리뷰는 있다: "한쪽은 70 한쪽은 30으로 계산해서 각각 40분 20분 이런 식으로도" (더치 Play 리뷰). |
| 귀갓길 막차 반영 | **차별점이 약해짐** | 어디서봄(2026-10-29 출시)이 "지하철 막차 시간을 미리 확인"과 "출발역과 귀가역까지 고려"를 내세운다. 쎈터로도 "귀가 시간 최소화"를 내세운다 [확인, 앱 설명 기준]. 두 앱이 **후보역마다 사람별 막차 시각을 비교해 주는지는 [미확인]**. 둘 다 평가 2~3개 수준의 신생 앱이라 아직 선점했다고 보기는 어렵다 [추정]. |

### 반반역의 차별점 (3개)
1. **"왜 이 역인지" 한 장으로 납득시키는 결과 카드.** 사람별 시간과 환승 횟수, 2위와의 차이를 문장으로 보여준다(예: "2위 합정보다 가장 오래 걸리는 사람이 6분 덜 걸려요"). 경쟁 서비스는 숫자만 나열하거나 점수만 보여준다. 이 카드는 따라 하기 쉬워 해자는 아니다. 그래도 리뷰 불만 1위("추천역이 공평하지 않다")에 대한 직접적인 답이다.
2. **"오늘은 ○○ 쪽으로" 배려 모드.** 확인한 경쟁 서비스 18곳(1.1절 표 15곳과 기타 3곳) 중 이 모드를 가진 곳은 없고, 사용자 요청은 있다. 생일이거나 짐이 많거나 퇴근이 늦은 사람처럼 실제 약속에서 자주 생기는 상황을 다룬다. 계산 비용도 낮다(목적 함수 가중치만 바꾸면 된다).
3. **귀갓길까지 보는 추천(막차)은 2차 핵심 기능으로 둔다.** 경쟁자도 주장하는 기능이라 단독 차별점은 아니다. 그래도 "후보역마다 각자 몇 시까지 놀 수 있는지"를 비교해 주면 저녁 술자리 약속에서 가장 강한 이유가 된다. **틀린 막차 정보는 정보가 없는 것보다 나쁘다.** 위밋플레이스 리뷰에는 시간이 30분 틀려서 "손절당할 뻔했다"는 사례가 있다. 그래서 시간표 데이터의 정확성이 검증되기 전에는 MVP에 넣지 않기를 권한다.

### MVP에 꼭 넣을 것
- 역 이름 입력 하나로 시작한다: 자동완성(초성 포함)과 "내 역" 기억. 주소 입력, 회원가입, 위치 권한은 없다.
- 2~4명 입력. **입력은 처음 사용자 한 명이 전부 한다** (친구가 직접 넣는 방 방식은 30초 목표와 맞지 않음).
- 결과 후보 3개. 1위는 크게, 2·3위는 접어서 보여준다.
- 카드마다 사람별 소요시간과 환승 횟수, 최장 시간과 시간 차이, 추천 이유 한 줄.
- 모드 탭 3개: 공평하게(기본) / 빨리 만나기 / 오늘은 ○○ 쪽으로.
- 카카오톡 공유: OG 미리보기 카드에 역 이름과 각자 시간이 바로 보이게 한다.
- 받은 링크는 설치·가입 없이 열린다. "내 이름"을 누르면 내 경로가 보인다.
- 지도 앱 연결: 카카오맵과 네이버지도 길찾기 딥링크.
- 극단 상황 안내: 누군가 90분을 넘거나, 모두 같은 동네이거나, 후보가 없을 때.

### MVP에서 뺄 것
- 회원가입·로그인, 전화번호 인증, "위치 항상 허용": 위밋플레이스 1점 리뷰의 가장 큰 원인이다.
- 채팅, 실시간 위치 공유, 친구 초대: 위밋플레이스가 넣은 뒤 "쓰지도 않을 채팅, 위치 공유" 반발이 나왔다.
- 맛집·카페 목록, 투표, 정산, 일정 조율: 경쟁 서비스가 모두 붙이는 기능이지만 핵심 질문("어느 역?")과 다르다. 지도 앱 링크로 대신한다.
- 버스, 자가용, 주소 입력, 출발지 숨기기.
- 막차 표시: 위 차별점 3 참고. 시간표 데이터가 검증되면 2차 1순위로 넣는다.

### 1.2 관찰
- **위밋플레이스는 사실상 멈춘 상태로 보인다 [추정].** 앱 최종 업데이트는 2022-02-17이다 [확인]. 2025-07-14에 "역 검색이 아예 안되고 있어요", "로딩하는 원만 계속 돌아가고"라는 리뷰가 3건 올라왔다 [확인]. 한국 Play 스토어에서 "위밋플레이스"를 검색하면 상위 결과에 나오지 않는다 [확인]. 웹은 JS 앱이라 동작 여부를 확인하지 못했다 [미확인].
- **2026년에 비슷한 앱이 쏟아졌다.** 너나중, 어디서 볼까?, 쎈터로, 모여, 만나역, 어디서봄이 모두 2026년 출시 또는 업데이트다. 그런데 평가 수는 0~8개, 다운로드는 1만+인 더치를 빼면 수백 이하다 [확인]. **아이디어 자체는 흔하고, 아직 확실한 승자는 없다.**
- **공평 기준은 minimax로 수렴하고 있다.** 우리지금만나, 중간에서 보자, 어디서 볼까?, 중간어디가 모두 "가장 오래 걸리는 사람 최소화"를 쓴다. 반반역이 고른 기준은 옳지만 그것만으로 차별화되지는 않는다.
- **거의 모든 서비스가 "주변 맛집"에 화면을 많이 쓴다.** 사용자 불만은 "갈 데 없는 역을 추천"하는 데서 나왔다(2.2절 B). 해결책은 맛집 목록이 아니라 **후보역을 약속 잡는 역으로 미리 추리는 것**이다. 브리프의 50~100개 후보역 결정이 이 불만에 대한 답이다.
- **카카오맵·네이버지도에는 중간지점 기능이 없다** [추정, 블로그가 "가장 멀리 떨어진 사람 사이 큰 환승역을 찾아 각자 길찾기로 확인"하는 수동 방법을 안내함]. 사용자는 길찾기를 두 번 돌려 직접 비교한다. 반반역의 실제 경쟁 상대는 앱보다 **"사당 어때?" 하고 각자 카카오맵을 켜는 습관**이다.

## 2. 사용자 불만 분류

리뷰는 주로 위밋플레이스 App Store 리뷰(2020~2025, 약 80건 중 불만 위주로 추림)에서 모았고, 더치 Play 리뷰와 쎈터로 App Store 리뷰를 보탰다. 블로그에서는 실제 불만 후기를 찾지 못했고, 사용 팁 형태의 "주의할 점"만 있어 별도로 적었다. 인용은 원문 그대로이며 날짜는 리뷰 작성일이다.

### A. 추천역이 공평하지 않다 / 이상하다 (가장 많음, 핵심 문제)
- "셋이 만나는데 한 명은 19분 나머지는 1시간 이상 시간이 걸린다고 떠요" (위밋, 2023-06-26, 4점)
- "진짜 구립니다 39분이랑 69분이 중간지점...?" (위밋, 2020-03-08, 1점)
- "차타고 40분 거리 사는 친구랑 2시간 30분 걸리는 장소에서 만나래요" (위밋, 2021-11-17, 2점)
- "지점과 지점을 선으로 잇고 그 중간지점을 찾아주시는 것 같은데 걸리는 시간이 비슷한 곳이면 가운데 지점이 아니어도 추천해줄 수 있으면" (위밋, 2022-03-29, 4점)
- "구미역(경상도)이랑 신정역(서울지하철5호선) 중간지점 찾으려고 하니까 신정역이라고 떴어서 이게뭐지" (더치 Play, 2020~2022)

→ **시사점:** 지리적 중간이나 불투명한 계산에 대한 불신이 가장 크다. 반반역의 출발점이 맞다. 결과 카드는 **"이 숫자가 왜 공평한지" 사용자가 스스로 확인할 수 있게** 보여줘야 한다.

### B. 주변에 갈 데가 없다 / 엉뚱한 동네
- "과천으로 꺾어서 만나래요 편의점 4개랑 주유소밖애 없는데 거기서 뭐해야됨?" (위밋, 2020-04-26, 1점)
- "이상한 장소에서 보라고하네" (위밋, 2021-07-28, 1점)

→ **시사점:** 후보역을 "약속 잡는 역"으로 미리 추리는 브리프 결정이 맞다. 맛집 목록이 아니라 **후보 집합 설계**로 풀어야 한다.

### C. 표시한 시간이 실제와 다르다 (신뢰 붕괴)
- "저는 1시간 4분, 친구는 1시간 2분이라고 해서 송파역에서 만나기로 했어요.. 그래서 1시간 전에 버스 탔는데 지도 어플에는 소요시간이 1시간 34분이 떠서 친구가 많이 화나서 손절당할 뻔했습니다" (위밋, 2022-08-19, 1점)
- 블로그 팁: "경의중앙선이나 경춘선처럼 배차 간격이 긴 노선을 이용하는 친구가 있으면 그 친구 시간까지 고려해야 합니다" (funissu)

→ **시사점:** 미리 계산한 시간이 **배차 대기를 빼먹으면** 이 불만이 그대로 생긴다. 표시 시간에 대기 시간을 넣고, 오차 허용 범위를 정해 검증해야 한다(6절). 시간이 틀리면 친구 관계 비용이 생기므로 신뢰가 곧 제품이다.

### D. 입력이 귀찮다 / 가입·권한 장벽
- "매번 검색하기 너무 귀찮아요. 몇몇 장소를 저장하는 기능이나 적어도 검색 기록이 저장되게는 해주세요." (위밋, 2022-12-14, 1점)
- "친구가 이 앱을 쓰지않으면 제가 계속 주소를 입력해야한다는 점이 조금 아쉽네요" (위밋, 2020-02-06, 4점)
- "위치하나 아는데 회원가입이니 나이성별 닉네임?ㅋㅋ귀찮아죽겠는데" (위밋, 2021-03-01, 1점)
- "일주일에 한번 있을까 말까한 약속장소 잡는 일에, 제 일상의 모든 위치정보를 제공해야 하는 것은 상식적으로 말이 안 됩니다." (위밋, 2020-07-21, 1점)
- "이름있는 빌라나 장소만 등록 가능하고 그냥 일반 주택은 서치 자체도 안되네요" (위밋, 2020-02-17, 1점)
- "친구들 회원가입 안해도 되서 타 앱에 비해 편합니다" (더치 Play, 긍정 리뷰. 장벽이 없는 것 자체가 장점으로 언급됨)
- "첫 사용 땐 입력창이 좀 헷갈렸는데, 친구 등록해두면 그다음부턴 빠르게 입력돼서" (쎈터로, 2026-06-29, 4점)

→ **시사점:** 가입 없음, 권한 없음, **역 이름 입력(주소 아님)**, "내 역" 기억. 주소 검색 실패도 불만이므로 MVP는 역 이름만 받는다.

### E. 원하는 기준으로 바꾸고 싶다 (기능 요청)
- "한쪽은 70 한쪽은 30으로 계산해서 각각 40분 20분 이런 식으로도 찾을 수 있게요" (더치 Play) → **배려 모드 수요**
- "대중교통 환승여부라던가 예상시간까지 선택 계산할 수 있으면 좋겠어요... 지하철 환승 1회까지 ok" (더치 Play) → **환승 횟수 표시·조건 수요**
- "특정모임지점을 입력하면 각각 거기까지 걸리는 시간도 자동으로 계산해주는 기능이 있으면" (위밋, 2022-01-10, 5점) → **"이 역은 어때?" 직접 비교 수요**
- "환승 적은 역 우선으로 잡아주는 옵션도 있고, 귀가 시간까지 같이 고려해주는 게 마음에 들었어요" (쎈터로, 2026-06-29, 4점) → **귀갓길 고려가 칭찬 포인트**
- 블로그 팁: "한 사람은 직통이고 다른 사람은 세 번 환승을 해야 한다면 저는 제가 조금 더 가는 편으로" (funissu) → 같은 시간이라도 **환승 횟수가 체감 부담**이다

### F. 서비스 안정성 / 지역 범위
- "어플로도 페이지로도 중간장소 검색이 안되는데 서비스 종료된건가요" (위밋, 2023-07-24)
- "역 검색이 아예 안되고 있어요 모든역이 안떠요" (위밋, 2025-07-14)
- "부산 사는데 / 중간지점 여의도역" (위밋, 2022-05-01), "혹시 시골은 안되나요?" (위밋, 2021-05-14)

→ **시사점:** 수도권 한정이라면 **입력 단계에서 범위를 분명히 알려야** 한다("수도권 지하철역만 돼요"). 서버 의존을 줄이면(미리 계산, URL에 상태 담기) "갑자기 안 돼요"를 줄일 수 있다.

### G. 원치 않는 소셜 기능
- "그 기능 이용하려고 이 어플 처음부터 쓴건데 무슨 쓰지도 않을 채팅, 위치 공유… 원하지않고 쓰지도 않을랍니다" (위밋, 2021-07-28, 1점)
- "꼭 친구초대해서 위밋해야한다는자체가 깔아야한다고 요구하는거같아서 싫고 그냥 위치 딱딱 써서 중간지점 나오게 하면되는것을" (위밋, 2020-06-13, 1점)

→ **시사점:** 핵심 계산 앞에 소셜 단계를 넣지 않는다.

## 3. 차별점 정리

결론 섹션의 3개를 다시 정리하면 다음과 같다.

| # | 차별점 | 해결하는 불만 | 경쟁 현황 | 방어력 |
|---|---|---|---|---|
| 1 | 납득되는 결과 카드 (사람별 시간·환승, 2위 대비 이유 문장) | A, C, E(환승) | 시간만 보여주는 곳은 많고, 환승과 이유까지 보여주는 곳은 확인 못 함 | 낮음 (쉽게 따라 함). 그러나 필수 |
| 2 | "오늘은 ○○ 쪽으로" 배려 모드 | E(70:30 요청) | 확인한 서비스 중 없음 | 중간 (아이디어는 쉽지만 문구와 UX로 앞설 수 있음) |
| 3 | 귀갓길 막차 비교 (2차) | E(귀가 칭찬), 저녁 약속 | 어디서봄·쎈터로가 유사 기능 주장 | 데이터 정확도에 달림. 정확하면 높음 |

**차별점이 아닌 것:** minimax 공평 기준, 사람별 시간 표시, 가입 없음, 카톡 공유, 지도 앱 연결. 모두 기본 기능이므로 빠지면 지고, 넣어도 이기지는 못한다.

## 4. MVP 화면 흐름 (첫 사용자 → 카톡 공유 30초)

### 4.1 흐름 요약과 시간 배분 (2인 기준)

```
[1 입력] ──탭──▶ [2 결과] ──탭──▶ [3 카톡 공유 시트] ──▶ (친구) [4 받은 링크]
 0~12초          12~22초           22~30초                  (30초 목표 밖)
```

| 단계 | 사용자 동작 | 목표 시간 |
|---|---|---|
| 첫 화면 진입 | 링크·홈 화면 아이콘으로 진입. 설명 화면이나 온보딩 없음 | 0초 |
| 내 역 입력 | "강" 입력 → 자동완성 "강남 2호선·신분당" 탭 (재방문이면 미리 채워짐) | ~5초 |
| 친구 역 입력 | 이름(선택)과 역 | ~6초 |
| 만날 역 찾기 | 버튼 탭 → 결과 즉시 표시 (미리 계산된 데이터라 0.5초 이내) | ~1초 |
| 결과 확인 | 1위 카드 읽기 | ~8초 |
| 공유 | "카톡으로 보내기" → 카톡 방 선택 → 전송 | ~8초 |
| **합계** | | **~28초** (3~4인은 +10초, 목표 45초) |

설계 원칙
- **입력은 한 사람이 전부 한다.** 약속을 주도하는 사람은 친구가 사는 역을 대개 안다. 친구가 들어와 입력하는 방 방식(우리지금만나, 중간에서 보자)은 정확하지만 결과가 나오기까지 친구를 기다려야 하므로 30초 목표와 맞지 않는다.
- **결과 상태를 URL에 담는다** (출발역과 모드). 서버 저장이나 계정 없이 링크만으로 같은 결과를 다시 만들 수 있다 (F 불만 대응, 개인정보 부담 감소) [권고. 구현 가능 여부는 알고리즘·데이터 담당과 확인 필요].
- 이름 칸은 선택이다. 비워 두면 "나 / 친구1 / 친구2"로 표시한다.

### 4.2 화면 1 — 입력 (홈)

```
┌─────────────────────────────────┐
│ 반반역                           │
│                                 │
│ 우리 어디서 만나야               │
│ 덜 억울할까?                     │
│ 각자 지하철 시간으로 계산해요      │
│                                 │
│ ┌─────────────────────────────┐ │
│ │ 나      [ 강남           ✕ ] │ │
│ │         2호선 · 신분당선      │ │
│ ├─────────────────────────────┤ │
│ │ 이름    [ 역 이름 입력      ] │ │
│ │ ┌───────────────────────┐   │ │
│ │ │ 합정  2·6호선          │   │ │
│ │ │ 합정(망원 방향) ...     │   │ │
│ │ └───────────────────────┘   │ │
│ └─────────────────────────────┘ │
│  + 한 명 더 (최대 4명)            │
│                                 │
│ ┌─────────────────────────────┐ │
│ │       만날 역 찾기  →        │ │
│ └─────────────────────────────┘ │
│ 수도권 지하철역만 돼요 · 가입 없음 │
└─────────────────────────────────┘
```

핵심 문구
- 제목: **"우리 어디서 만나야 덜 억울할까?"**
- 부제: "각자 지하철 시간으로 계산해요" (지리적 중간이 아니라는 신호. A 불만 대응)
- 입력 칸 안내: "역 이름 입력 (예: 홍대입구)"
- 범위 안내: "수도권 지하철역만 돼요 · 가입 없음" (F·D 불만 대응)
- 오류 처리: 수도권 밖 입력 → "아직 수도권 지하철역만 계산할 수 있어요"

동작 세부
- 자동완성은 초성("ㅎㄷ"), 역 이름 생략형("홍대"), "역" 접미사 유무를 모두 받는다.
- "나" 칸은 마지막 입력값을 기기에 기억한다(localStorage. 실패해도 동작에는 영향 없음).
- 같은 역을 두 명이 넣으면 그대로 허용한다(같이 출발하는 경우).
- 입력 2개가 차면 버튼이 활성화된다. 엔터만 쳐도 결과로 간다.

### 4.3 화면 2 — 결과

```
┌─────────────────────────────────┐

│  ━━━━━━                         │
│ ┌─────────────────────────────┐ │
│ │ 1  신촌  2호선               │ │
│ │                             │ │
│ │ 나      ████████░░  34분 환승1│ │
│ │ 지훈    █████████░  38분 환승0│ │
│ │                             │ │
│ │ 💬 가장 오래 걸리는 지훈도 38분.│ │
│ │    2위 합정보다 4분 덜 걸려요.  │ │
│ │                             │ │
│ │ [지도에서 보기]   [길찾기 ▾]  │ │
│ └─────────────────────────────┘ │
│ ┌─────────────────────────────┐ │
│ │ 2  합정   최장 42분 · 차이 6분 ▸│ │
│ ├─────────────────────────────┤ │
│ │ 3  을지로3가 최장 43분 · 차이 2분▸│ │
│ └─────────────────────────────┘ │
│                                 │
│ ┌─────────────────────────────┐ │
│ │  💛 카톡으로 보내기           │ │
│ └─────────────────────────────┘ │
│   링크 복사                      │
└─────────────────────────────────┘
```

핵심 문구
- 모드 탭: **"공평하게" / "빨리 만나기" / "○○ 쪽으로"** (○○에는 입력한 이름이 들어간다. 탭하면 누구 쪽으로 할지 고른다)
- 공유 버튼: **"카톡으로 보내기"** (보조: "링크 복사")
- 시간 표시는 막대와 숫자를 함께 쓴다. 막대 길이는 같은 카드 안에서 최장 시간을 기준으로 한다.
- "환승 0"은 "환승 없음"으로 쓴다.

극단 상황 문구
- 최장 시간이 90분을 넘을 때: "누군가는 90분 넘게 걸려요. 한쪽 동네에서 만나는 게 나을 수도 있어요 → [○○ 쪽으로 보기]"
- 모두 같은 역이나 아주 가까운 역일 때: "이미 같은 동네예요. ○○역에서 만나세요"
- 후보 간 차이가 1~2분뿐일 때: 1위 카드 아래에 "세 곳 다 비슷해요. 가고 싶은 동네로 고르세요"라고 표시한다(순위를 과장하지 않음).

### 4.4 화면 3 — 카톡 공유 (시스템 공유 시트 / 카카오 공유)

카톡 말풍선(OG 미리보기) 예시

```
┌───────────────────────────────┐
│ [이미지: 신촌 · 나 34분 · 지훈 38분]│
│ 신촌에서 볼까? (2호선)          │
│ 나 34분 · 지훈 38분 · 공평하게 고름│
│ ─────────────────────────────  │
│        후보 3곳 보기             │
└───────────────────────────────┘
```

핵심 문구
- 제목: **"{1위역}에서 볼까?"** (결정이 아니라 제안하는 말투. 받는 사람이 거절할 여지를 남긴다)
- 설명: "{이름} {분}분 · {이름} {분}분 · {모드}로 고름"
- 버튼: "후보 3곳 보기"
- 미리보기만 봐도 **각자 시간**이 보이게 한다. 링크를 열지 않아도 대화가 진행되게 하기 위해서다.

### 4.5 화면 4 — 받은 링크 (친구 쪽, 설치 없음)

```
┌─────────────────────────────────┐
│ 반반역                           │
│ 민지가 고른 만날 역 후보           │
│                                 │
│ 나는 누구?  [민지] [지훈✓]        │
│                                 │
│ ┌─────────────────────────────┐ │
│ │ 1  신촌  2호선               │ │
│ │ 지훈(나) 38분 · 환승 없음      │ │
│ │   합정 → 2호선 → 신촌         │ │
│ │ 민지     34분 · 환승 1        │ │
│ │ 💬 가장 오래 걸리는 사람도 38분 │ │
│ │ [카카오맵 길찾기] [네이버지도]  │ │
│ └─────────────────────────────┘ │
│  2 합정 ▸   3 을지로3가 ▸         │
│                                 │
│ 기준 바꿔 보기: 공평 | 빨리 | 쪽으로 │
│                                 │
│  나도 다른 조합으로 찾아보기 →     │
└─────────────────────────────────┘
```

핵심 문구
- 헤더: **"{보낸 사람}이 고른 만날 역 후보"**
- "나는 누구?" 선택 시 내 줄을 맨 위로 올리고 내 경로를 한 줄로 보여준다(노선 순서).
- 받는 사람도 모드를 바꿔 볼 수 있다. URL만 바뀌므로 서버 상태는 없다.
- 하단 CTA: "나도 다른 조합으로 찾아보기" (신규 사용자 유입 경로)
- 투표와 출발역 수정은 MVP에서 뺀다 (브리프 범위).

## 5. 추천 결과 카드 정보와 "추천 이유" 문구

### 5.1 카드에 보여줄 정보 (우선순위 순)

| 순위 | 정보 | 이유 |
|---|---|---|
| 1 | 역 이름 + 노선 배지 | 어디인지 |
| 2 | 사람별 소요시간 (막대 + 분) | 공평 여부를 사용자가 직접 확인 (A) |
| 3 | 사람별 환승 횟수 | 같은 시간이라도 체감 부담이 다름 (E, 블로그 팁) |
| 4 | 추천 이유 한 줄 | 왜 1위인지, 2위와 무엇이 다른지 |
| 5 | 지도 보기 / 길찾기 딥링크 | 결정 후 행동 |
| 2차 | 사람별 막차("23:40까지 가능") | 저녁 약속 (차별점 3) |
| 접힌 카드 | 최장 시간 · 시간 차이 | 2·3위를 펼치지 않고도 비교 |

넣지 않을 것: 종합 "공평 점수"(브리프 원칙, 불투명), 별점, 맛집 썸네일.

표시 시간 규칙 [권고, 데이터 담당과 맞출 것]: 표시 시간 = 승차역 대기(배차 간격의 절반) + 차내 시간 + 환승 도보와 대기. 대기 시간을 빼면 C 불만("1시간 4분이라더니 1시간 34분")이 다시 생긴다. 정류장까지 걷는 시간은 사람마다 달라 제외하되, 카드 하단에 "역에서 역까지 기준"이라고 작게 적는다.

### 5.2 "추천 이유" 문구 예시

문장 규칙: ① 한 줄, 40자 안팎 ② 숫자는 분 단위 ③ 비교 대상(2위 또는 다른 모드)을 밝힌다 ④ **손해 보는 사람이 있으면 숨기지 않는다**.

**공평하게 (minimax, 동점이면 시간 차이)**
- 기본: "가장 오래 걸리는 지훈도 38분. 2위 합정보다 4분 덜 걸려요."
- 동점으로 갈린 경우: "최장 시간은 합정과 같은 38분이지만, 두 사람 차이가 더 작아요 (4분 vs 12분)."
- 환승이 갈린 경우: "합정과 시간은 같고, 둘 다 환승 1번 이하예요."
- 3~4명: "넷 중 가장 먼 사람도 45분. 모두 35~45분 사이예요."
- 전원 장거리: "누구 한 명만 멀지는 않지만, 다 같이 50분대예요."

**빨리 만나기 (총 이동시간 최소)**
- 기본: "둘이 합쳐 58분, 후보 중 가장 짧아요. 대신 지훈이 민지보다 14분 더 걸려요."
- 공평 1위와 같은 역일 때: "가장 빠르면서 공평하기도 한 역이에요."
- 3~4명: "넷의 이동시간 합이 가장 작아요 (총 2시간 40분). 가장 먼 사람은 52분."

**오늘은 ○○ 쪽으로 (특정인 부담 최소)**
- 기본: "민지는 15분, 환승 없이 와요. 지훈은 공평하게보다 9분 더 걸려요 (47분)."
- 이유를 붙일 여지(선택 칩, 문구만): "오늘 생일이라서 / 짐이 많아서 / 늦게 끝나서". 칩을 고르면 공유 미리보기 문구가 바뀐다: "오늘은 민지 쪽으로 (생일🎂)". 계산에는 영향이 없다.
- 과하게 기울 때: "지훈이 60분을 넘어서, 조금 덜 기운 역을 골랐어요." [알고리즘 담당과 상한 규칙 확인 필요]

**2차: 막차 문구 (참고)**
- "여기서 만나면 민지는 23:40, 지훈은 00:15까지 놀 수 있어요."
- 경고: "지훈은 23:05 막차예요. 늦게까지 놀 거면 2위 합정이 나아요 (00:10까지)."

## 6. 검증 계획 (친구 모임 테스트)

### 6.1 방식
- 대상: 실제로 약속을 잡는 친구 모임 **6~8개** (2인 3개, 3~4인 3~5개). 출발지가 서울과 경기·인천에 섞인 조합을 반드시 포함한다.
- 기간: 2주. 약속을 잡는 사람(주최자)에게 링크만 준다. 사용법 설명이 필요하면 그 자체를 문제로 기록한다.
- 도구: 익명 이벤트 로그(역 이름은 남기되 개인 이름은 남기지 않음), 만난 뒤 각자 1분 설문, 2~3개 모임은 첫 사용을 옆에서 관찰(스톱워치·화면 녹화).

### 6.2 측정 지표와 목표

| 질문 | 지표 | 측정 방법 | 목표 (통과 기준) |
|---|---|---|---|
| 30초 안에 공유하나? | 첫 진입 → 공유 탭까지 시간 | 이벤트 로그 + 관찰 | 2인 중앙값 ≤ 30초, 90%가 ≤ 45초 |
| 막히는 곳은? | 입력 단계 이탈률, 자동완성 실패 검색어 | 로그 | 실패 검색어 목록을 확보해 사전 보강 |
| 결과를 믿나? | 공유 전에 카카오맵 등으로 "검산"한 비율 | 관찰 + 설문 "따로 확인했나요?" | 검산 비율 감소 추세 (초기 기준선 기록) |
| 시간이 맞나? | 표시 시간과 실제 소요의 차이 | 만난 뒤 "실제로 몇 분 걸렸나요?" (각자) | 80% 이상이 ±5분 이내, ±15분 초과는 0건 |
| 왜 1위인지 아나? | 카드만 보고 "왜 여기?"를 설명할 수 있는 비율 | 관찰 중 질문 | 80% 이상 |
| 공평하다고 느꼈나? | "덜 억울했다" 1~5점 (각자, 특히 가장 먼 사람) | 설문 | 가장 먼 사람 평균 ≥ 4 |
| 추천을 채택했나? | 실제 만난 역이 1위 / 2·3위 / 목록 밖인 비율 | 설문 | 상위 3곳 채택 ≥ 70% |
| 안 고른 이유는? | 1위를 버린 이유 (갈 데 없음 / 낯섦 / 시간 불신 / 기타) | 설문 자유 응답 | 후보역 목록 보정에 사용 |
| 모드를 쓰나? | 기본 외 모드 탭 비율, 배려 모드 사용 상황 | 로그 + 설문 | 배려 모드 사용 사례 수와 이유 수집 (차별점 2 검증) |
| 링크가 퍼지나? | 공유 1회당 링크 열람 수, 받은 사람의 "나도 찾아보기" 탭 비율 | 로그 | 열람 ≥ 참가 인원의 70% |
| 막차가 필요한가? | 저녁(19시 이후) 약속 비율, "몇 시까지 있을 수 있는지 알았으면?" 응답 | 설문 | 저녁 약속의 50% 이상이 "필요"라고 답하면 2차 1순위 확정 |
| 다시 쓰나? | 2주 안에 같은 주최자의 재사용 | 로그 (기기 단위) | 주최자 30% 이상 재사용 |

### 6.3 중단·전환 기준
- 시간 오차 ±15분 초과가 2건 이상이면 확장을 멈추고 소요시간 데이터부터 고친다 (C 불만이 가장 치명적).
- 상위 3곳 채택이 50% 미만이고 주된 이유가 "갈 데 없음"이면 후보역 목록을 다시 짠다.
- 배려 모드를 아무도 쓰지 않으면 차별점 2를 재검토한다(탭에서 빼고 메뉴로 옮긴다).

## 결정 필요

1. **막차를 MVP에 넣을지.** 권고는 "넣지 않고 2차 1순위"다. 시간표 기반 막차 계산은 미리 계산한 역간 시간과 다른 데이터가 필요하고, 틀리면 신뢰가 무너진다. 데이터 담당의 결론에 따라 다시 판단해야 한다.
2. **입력 방식: 한 사람이 전부 입력(권고) vs 친구가 링크로 들어와 각자 입력.** 후자가 더 정확하지만 30초 목표와 충돌한다. 받은 링크에서 "내 역 고치기"를 허용할지도 정해야 한다(허용하면 상태 저장이 필요할 수 있음).
3. **결과 상태를 URL에만 담을지(서버 저장 없음).** 링크에 역 이름과 이름이 그대로 노출된다. 이름 칸을 선택 사항으로 두면 부담이 줄지만 결정이 필요하다.
4. **표시 시간에 배차 대기를 넣는 방식** (배차 간격의 절반 등). 데이터·알고리즘 담당과 합의해야 한다.
5. **배려 모드의 상한 규칙.** 배려받는 사람 시간을 줄이는 대신 다른 사람 시간이 공평 1위보다 얼마까지 늘어도 되는지(예: +15분 또는 60분 상한).
6. **경쟁이 붐비는 상황에서의 포지셔닝.** 2026년에 비슷한 앱이 6개 이상 나왔다. 앱 대신 "웹 링크 우선"으로 갈지 결정해야 한다. 권고는 웹 우선이다. 카톡 공유 후 설치 없이 열리는 것이 핵심 동선이고, 경쟁 앱 다수는 설치를 요구한다.
7. **어디서봄·쎈터로의 실제 막차·귀가 기능 수준을 직접 설치해 확인할지.** 이번 조사는 스토어 설명과 리뷰만 봤다 [미확인 항목].
