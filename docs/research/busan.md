# 부산 도시철도 계산 조사: 데이터·허용 범위·작업량 (#180)

조사일 2026-11-25(아래 "확인"은 모두 이 날짜). 조사만 했고 코드·설정·데이터는 바꾸지 않았다. 키가 필요한 API는 부르지 않았다. 공개 파일은 저장소 밖 임시 폴더에 받아 열어 봤고 커밋하지 않았다(재현용 SHA-256은 2절).
**[확인]**은 직접 받아서 열거나 공식 페이지에서 읽은 것, **[추정]**은 확인한 사실에서 이끌어 낸 것이다. 법률 판단은 하지 않았다.

> **독립 검토 반영(2026-11-25).** 다른 계열 모델(Codex)이 원본을 다시 받아 해시·기준일·이용허락 표기를 대조했다. 지적은 모두 근거를 다시 열어 확인한 뒤 고쳤다. 주요 정정은 다섯 가지다. ① 환승 보행 수치의 공개 단편(연산역 182→109초, 6개 역 휠체어 환승 거리)이 있다. ② 코레일의 2026-09 동해선 시각표(열차번호 포함)가 있다. ③ 서울 보행 추정값과 여유 규칙으로는 부산 막차의 '이른 쪽 오차'를 보장할 수 없다. ④ B1·B2는 CP949 인코딩이고 대조 수치가 일부 달랐다. ⑤ BGL 날짜 표기를 고쳤다.

> **막차 빈칸 재조사(2026-11-26).** [busan-last-train.md](busan-last-train.md)가 이 문서의 두 가지를 고쳤다. ① B6 공식 명세에는 환승구분 항목이 있고, 옛 API(15001019)의 제3자 수집본에는 12개 환승역의 환승 거리·시간 값이 있다(1절 B6 행의 "보행시간 필드는 없다"는 틀림). 값은 키로 직접 받아 역 쌍·단위를 확인하기 전까지 후보다. ② 부산교통공사가 2026-08-24부터 1~4호선 토요일·휴일과 평일 2·4호선 시각표를 바꿨고 평일 1·3호선도 일부 역을 1분 안팎 조정했으므로, B1(2026-07-22)은 어느 요일에도 현행판이 아니다. 막차 칸별 판단은 그 문서의 결론 표를 따른다.

## 결론

**부산은 1~4호선 원천이 수도권보다 좋다. 자체 그래프 사전계산(01-synthesis '데이터')을 그대로 적용할 수 있다.** 부산교통공사가 1~4호선 **열차별 시각표 파일**을 공공데이터포털에 올려 두었다. 열차번호, 역마다 도착·출발 시각, 평일·토·공휴일이 있고, 기준일은 2026-07-22, 이용허락범위는 '제한 없음'이다. 수도권 TAGO처럼 열차 ID 없이 봉우리를 찾아 추정하지 않아도 된다.

가장 큰 빈칸은 **환승 보행시간**이다. 서울 S4처럼 전수이면서 재사용 조건이 분명한 표는 확보하지 못했다. 공개된 단편 수치(연산역, 6개 역 휠체어 경로 실측)는 대조 근거로만 쓸 수 있다. 그래서 **막차는 끈 채로 출시**한다. 현행 공식표와 대조하고 환승이 검증된 칸만 나중에 켠다.

- 정거장 번호 `001-…`은 **열차마다 1부터 세는 순번**이다. 공식 역번호(B2·B3의 95~414, TAGO의 `MTRBS10095`)가 아니다. 그래서 역은 이름으로 맞춘다. 이름 표기가 다른 것이 1건 있다: B1 `국제금융.부산은행`, B2 `국제금융센터.부산은행`.
- 시각은 **분 단위**다(서울 S5·TAGO는 초). 중간역 정차는 0분 61,801칸, 1분 39,431칸, 2~7분 204칸이다. 2분 이상은 회차·대기로 보인다.
- **결함 있는 열차가 2대 있다.**
  - 2호선 평일 열차 2453은 정거장 26, 도착 43, 출발 26으로 수가 맞지 않는다.
  - 1호선 공휴일 13시대 열차 1대는 모든 중간역(38곳)에서 출발이 도착보다 17~18분 이르다. 다른 열차의 출발 열이 들어간 것으로 보인다.
  - 파서가 이런 열차를 격리하고 그 수를 보고서에 남겨야 한다.
- 종착역 출발 시각은 `040-:`처럼 비어 있다. 자정을 넘는 열차가 68대 있다(4호선 미남 출발 00:02·00:12·00:20, 3호선 수영 23:59 출발 등).
- 평시(10~16시) 기점 출발 간격의 중앙값은 1호선 6분, 2·3호선 7분, 4호선 8분이다. 밤(21~24시)에는 10분이다.
- 평일 기점 막차 출발:
  - 1호선: 노포 23:16(다대포행)·23:31(신평행), 다대포해수욕장 23:11
  - 2호선: 장산 23:11(양산행)·23:26(호포행)·23:43(광안행), 양산 23:07
  - 3호선: 수영 23:59, 대저 23:40
  - 4호선: 안평 23:44, 미남 00:20

**B1과 B2(공식 역간 소요시간)의 대조.** 집계 규칙은 다음과 같다.
- 평일 열차만 쓴다. 위 결함 열차는 뺀다(정거장·시각 수가 다르거나, 중간역 정차가 60분을 넘는 열차. 평일에는 2453 한 대).
- 방향은 B2의 역번호가 커지는 쪽(B2 행 순서)만 본다.
- 열차마다 A 출발 → B 도착(분×60)을 재고, 자정은 1440분으로 나눈 나머지로 처리한다. 쌍마다 열차들의 중앙값을 낸 뒤 B2를 뺀다. 표는 쌍들의 중앙값(`statistics.median`, 짝수 개면 두 가운데의 평균)이다.
- B2의 110쌍 가운데 이름 별칭(국제금융) 때문에 못 맞춘 2쌍을 빼 **108쌍**이다.
- 출발→출발은 B의 출발 시각이 있어야 하므로, 종착역에 닿는 구간을 뺀 **104쌍**이다.

방향을 바꾸면(역번호가 작아지는 쪽, 별칭 적용 110쌍) 도착 기준 중앙값은 −10/+7.5/−5/−10초다. 이번 판의 첫 표는 노선별 순위 위치로 중앙값을 냈고 두 방향을 섞었다. 그래서 3호선(+5초)과 출발→출발 칸이 달랐다. 위 표로 고쳤다.

B2의 소요시간은 정차를 뺀 주행시간이다. 출발→출발(정차 포함)로 재면 +25~30초가 된다. 수도권 D1의 S3 대 TAGO 대조(p50 +30초)와 같은 모양이다. 지금 간선 규칙(앞 역 출발→다음 역 도착 + 도착역 정차, D1 7.1절)을 그대로 쓸 수 있다. 분 단위 반올림 때문에 쌍 하나하나는 ±1분 안에서 흔들린다. 쌍마다 하루치 중앙값을 쓰면 그 흔들림이 거의 사라진다.

재현(표준 라이브러리만, `B1.csv`·`B2.csv`는 받은 원본 그대로):

```python
import csv, io, statistics, collections
rd = lambda p: list(csv.DictReader(io.StringIO(open(p, "rb").read().decode("cp949"))))
b1, b2 = rd("B1.csv"), rd("B2.csv")
LINE = {"1": "부산 도시철도 1호선", "2": "부산 도시철도 2호선", "3": "부산 도시철도 3호선", "4": "부산 경량도시철도 4호선"}
def m(s):
    s = s.split("-", 1)[1]
    return None if s in (":", "") else int(s[:2]) * 60 + int(s[3:5])
arr, dep = collections.defaultdict(list), collections.defaultdict(list)
for r in b1:
    if r["요일구분"] != "평일": continue
    st = [x.split("-", 1)[1] for x in r["운행구간정거장"].split("+")]
    a = [m(x) for x in r["정거장도착시각"].split("+")]; d = [m(x) for x in r["정거장출발시각"].split("+")]
    if not (len(st) == len(a) == len(d)) or any(x is not None and y is not None and (y - x) % 1440 > 60 for x, y in zip(a[1:-1], d[1:-1])): continue
    for i in range(len(st) - 1):
        if d[i] is None or a[i + 1] is None: continue
        k = (r["노선명"], st[i], st[i + 1])
        arr[k].append((a[i + 1] - d[i]) % 1440 * 60)
        if d[i + 1] is not None: dep[k].append((d[i + 1] - d[i]) % 1440 * 60)
for no, ln in LINE.items():
    rows = [x for x in b2 if x["호선"] == no]
    for name, tab in (("arr", arr), ("dep", dep)):
        dl = [statistics.median(tab[(ln, p["역명"], q["역명"])]) - (int(q["소요시간(분)"][:2]) * 60 + int(q["소요시간(분)"][3:]))
              for p, q in zip(rows, rows[1:]) if tab.get((ln, p["역명"], q["역명"]))]
        print(no, name, len(dl), statistics.median(dl), min(dl), max(dl))
```

- 웹 노선 표시명은 이미 `부산1호선`~`부산3호선` 꼴로 정규화돼 있다(`web/scripts/station-lines.ts`). 그래프 계통 이름(`rg.bin`의 `displayLine(group)`)은 수도권 `1`과 겹치지 않게 `부산1` 같은 이름이 필요하다.

## 5. 설계 영향과 작업량

### 5.1 지역 모델 (권고: 전국 한 벌 + 지역 태그)

| 안 | 내용 | 좋은 점 | 나쁜 점 |
|---|---|---|---|
| **A. 전국 한 벌(권고)** | 그래프·od.bin·lt.bin·rg.bin을 지금처럼 하나로 둔다. 축에 부산 역과 부산 후보를 더하고, 다른 지역 칸은 `0xFFFF`(도달 불가, data-format §4)로 둔다. stations.json 역마다 `region`을 둔다 | od.bin 형식·서버 로더·manifest 구조를 그대로 쓴다. 순위 코드(`Rank`)는 도달 불가 후보를 이미 뺀다. 공평 순위(minimax)를 건드리지 않는다 | 빈 칸이 생긴다. 800×152 ≈ 12.2만 칸, 지역별로 나누면 약 8.7만 칸(+40%). 구분 8개 + od + lt를 합쳐도 수 MB 안이다 |
| B. 지역별 파일 | manifest가 지역마다 od·rg·lt를 가리킨다 | 빈 칸이 없고 지역마다 따로 발행한다 | manifest·계약·서버 로더·SEO·게이트를 모두 지역 단위로 바꿔야 한다. 작업이 1.5~2배 |

A로 가도 대구·대전·광주를 더하면(원천 K1에 다 있음: 대구 2025-03-31, 대전 2026-06-25, 광주 2025-09-09) 약 1,000 × 200칸이다. 문제가 되면 그때 B로 나눈다.
- **지역 정의의 원본은 M1의 '권역'**이다(손으로 적지 않는다, #146 원칙). 그래프 연결 성분과 권역이 같은지 게이트로 검사한다.
- 권역 '부산'에는 동해선 울산 구간(서생~태화강)과 김해가 들어 있다. 화면 이름을 '부산'으로 할지 '부산·울산·김해'로 할지는 운영자가 정한다.

**한 방 = 한 지역.** 웹은 첫 출발역의 지역을 정한 뒤 다른 지역 역을 고르면 막는다. 서버는 지역이 섞인 요청에 새 문제 코드(예: `REGION_MISMATCH`)를 낸다. 지금은 모든 후보가 도달 불가로 빠져 빈 결과가 된다. 계약 변경이라 운영자 병합 대상이다.

- **처리방침**: 수집 정보는 그대로다. 통계 이벤트에 '지역'을 넣으면 이용 통계 항목이 바뀌므로 **재동의가 필요**하다. 넣지 않는 것을 권한다(출발역도 이벤트에 넣지 않는 원칙과 같다).

### 5.3 대구·대전·광주로 넓히기

K1 한 파일에 대구 1~3호선(2025-03-31, 평일·토·휴일), 대전 1호선(2026-06-25), 광주 1호선(2025-09-09, '명절'까지)이 열차번호와 함께 들어 있다. TAGO 역 목록에도 있다. **설정·게이트·웹을 처음부터 '지역' 단위로 만들고, 데이터는 부산만 넣는 것**을 권한다. 그러면 다음 지역은 PR 2·3의 데이터 부분(M)만 남는다. 지역마다 갱신 일자가 다르므로 영수증·신선도를 지역별로 둔다.

## 7. 운영자가 정할 것

1. **진행 여부와 범위.**
   - 부산 1~4호선 + 부산김해 + 동해선(울산 태화강까지)으로 할지.
   - 양산선(2026-12 개통 예정)은 첫 출시에서 빼는 것을 권한다.
   - L 크기 작업 전에 수요 신호(부산 사용자 문의, 범위 밖 검색)를 볼지.
2. **지역 모델.** 전국 한 벌 + 지역 태그(권고 A) 대 지역별 파일(B). 지역 원본을 M1 '권역'으로 할지.
3. **지역 이름.** 화면에 '부산'으로 쓸지 '부산·울산·김해'로 쓸지. 첫 화면·#170 안내·OG·SEO 문구.
4. **섞인 지역 처리.** 모든 진입점(직접 추천·기존 링크·방 생성/참여/수정)에서 막고 서버는 새 문제 코드를 낼지(계약 변경). 숨긴 출발역의 지역을 어디까지 보일지.
5. **부전.** 1호선·동해선 두 코드를 보존하고 외부 도보 환승 간선을 더할지(권고), 한 물리역으로 합칠지.
6. **막차.** 부산은 끈 채 출시할지(권고). 켤 때는 현행 공식표와 노선·요일·행선지 대조를 통과하고 환승이 검증된 칸으로 한정할지.
7. **환승 보행.** 기본값 89초와 긴 환승 221초를 3절 목록에 쓸지. 부산교통공사에 환승 소요시간을 문의할지(정보공개청구 포함).
8. **동해선 원천.** 코레일에 K2(2026-09 시각표)의 재사용 조건을 문의할지. 그 전에는 대조용으로만 쓴다.
9. **TAGO 수집.** 코디네이터가 BGL·동해선 264개 조합(대조용 1~4호선 +684개)을 받을지.
10. **카카오맵 손 대조.** 누가 20~30쌍을 기록할지.
11. **후보·SEO.** 부산 후보 25~30개 제안을 사람이 검토할지. SEO 상한을 올릴지, 지역별 파일로 나눌지.
12. **통계.** 이벤트에 지역을 넣지 않을지(넣으면 재동의).
