## 1. 계산

설계안에서 달라진 것과 구현·검토에서 찾은 것만 적는다.

**열차 다시 잇기(chain v2).** 번호 없는 노선(TAGO)은 역별 시간표의 줄을 이어 열차를 다시 만든다.
- 같은 종착역의 줄만, **종착역 쪽 이웃**으로만 잇는다(노선 묶음의 역 그래프에서 종착역에 더 가까운 이웃. 여행 그래프의 주행 간선에서 얻는다). 종착역을 그래프에 놓지 못하면 잇지 않는다. 같은 (역, 종착역)의 줄이 가장 많이 맞는 이웃 하나만 쓴다.
- 다음 역 줄에 도착 시각이 있으면 **도착**을 "이 역 출발 + 주행 시간"과 견주고, 없으면 출발을 "이 역 출발 + 역간 시간"과 견준다. 허용 오차 ±90초.
- 다음 역의 줄은 **이 줄의 출발보다 뒤**여야 한다.
- **모호하면 잇지 않는다.** 둘째로 가까운 후보가 가장 가까운 후보와 60초 안이거나, 한 줄을 두 줄이 60초 안에서 다투면 끊는다. 끊긴 열차는 이른 쪽으로만 틀린다.
- 서울 1~8호선(S5)은 열차 번호로 묶는다. 서울 구간으로 이어 달리는 열차는 경계역에서 같은 묶음·같은 종착역·출발 45초 안이면 한 열차로 합친다.

검토의 반례(완행 A 23:00 → B 23:02 도착·23:12 출발 → C 23:14, 급행 A 23:10 → B·C 통과)는 v1에서 완행의 B 출발 줄(23:12)에 급행의 C 통과 줄이 이어져 A→C가 23:10으로 나왔다. v2는 B에서 도착 시각(23:02)으로 맞추므로 완행이 한 열차로 이어지고, 급행의 통과 줄은 정차가 아니다. A→C는 23:00(원천 여유를 빼 22:57, 화면 22:50)이다. `pipeline/src/test/resources/last-train/overtake.json`으로 Kotlin과 오라클 양쪽에서 고정했다.

**도착 시각이 없는 줄은 정차가 아니다.** TAGO는 급행이 지나가기만 하는 역에도 줄을 싣고, 그 줄은 도착 시각이 비어 있다(9호선 증미: 평일 19시 이후 145줄 중 68줄).
- 내릴 수 있는 곳: 도착 시각이 있는 줄.
- 탈 수 있는 곳: 도착 시각이 있는 줄, 또는 열차가 운행을 시작하는 줄(이은 열차의 첫 줄이고, 앞 역에 같은 종착역 열차가 예상 시각 ±5분 안에 없을 때). 앞 역에 그런 열차가 있으면 끊긴 급행일 수 있으므로 타지 못하는 줄로 본다(이른 쪽).

**원천 여유 3분.** 운영사 공식 시간표와 대조를 통과하지 못한 시간표의 열차는 **출발 3분 전까지 타는 것**으로 계산한다(`LT_SOURCE_MARGIN` 180초, 보고서의 `sourceMarginSeconds`).
- 근거: TAGO 원자료가 운영사 개정판과 다를 수 있다. 휴일 9호선에서 TAGO가 운영사 파일보다 역 쌍 225개에서 늦었고 최대 120초였다(열차 잇기 규칙을 고치기 전 측정으로는 242쌍, 최대 125초). 평일은 18쌍, 최대 35초. 관측한 최댓값(2분 남짓)에 1분을 더해 3분으로 잡았다.
- 붙는 곳: 번호 없는 줄로 다시 이은 열차(대조를 통과한 `exact` 노선·요일 제외), 그리고 그날 운영사 파일 대조를 통과하지 못한 서울 번호 노선.
- 붙지 않는 곳: 대조를 통과한 노선·요일 종류의 열차, 운영사 파일(S7) 자체의 열차.
- 게이트: 대조한 모든 노선에서 "우리가 늦은 최댓값 ≤ 180초"가 아니면 발행하지 않는다. 원천이 3분 넘게 어긋나면 여유를 키우거나 그 노선을 꺼야 한다는 뜻이다.
- 여유 시각은 화면에서 10분 단위로 내리므로, 3분을 빼도 보이는 값이 그대로인 칸이 많다(23:50 열차는 23:47 → 화면 23:40. 빼기 전에도 화면은 23:50이었으므로 이 칸은 10분 이르게 보인다).

**둘째 원천(S7).** 열차코드가 있는 운영사 공식 파일이 함께 있는 TAGO 노선(1·3·4·7·8·9호선의 TAGO 구간)은 표를 두 번 계산한다: TAGO 줄로 다시 이은 열차로 한 번, 운영사 파일의 열차로 한 번. 칸마다 **화면에 더 이르게 보이는 쪽**을 쓰고, 한쪽이라도 길을 못 찾으면 확인 필요다. 어느 쪽이 현행 시간표든 보인 시각에 타면 집에 간다. 둘째 원천 때문에 값이 바뀐 칸은 평일 40, 휴일 426이다.

**역방향 탐색.** 상태는 (역, 노선 묶음)이다. 갈아탈 때마다 `max(10분, 걷는 시간 × 2 + 5분)`을 둔다. 걷는 시간은 여행 그래프의 환승 간선에서 묶음 쌍별로 가져오고(방향별), 쌍이 없으면 그 역에서 가장 긴 값, 그것도 없으면 0이다. 같은 묶음 안에서 열차를 바꾸는 것도 10분이다. 20:00~27:00에 타는 열차만 본다.

**분류.** 표에는 원천 여유를 뺀 분이 그대로 들어간다(10분 단위 내림은 화면 몫).
- 직행 확정: 열차 한 대로 가고, **타는 줄과 내리는 줄이 모두** 대조를 통과한 노선·요일 종류의 것(3절).
- 여유 시각: 갈아타는 길, 또는 대조를 통과하지 못했거나 대조할 공식표가 없는 노선·구간의 직행. 갈아타는 길은 10분 단위로 내린 값이 직행의 보이는 값보다 늦을 때만 고른다.
- 확인 필요: 길을 못 찾음.

**토요일(운영자 결정).** `data/config/last-train.json`의 `days`가 요일 종류별 노선 허용 목록이다. 토요일은 서울교통공사 1~8호선만 있다. 목록에 없는 노선의 줄은 아예 읽지 않으므로, 나온 길은 모두 허용된 노선으로만 이어진다. TAGO 토요일 시간표를 받게 되면 `tagoGroups`에 묶음을 더하고 `build`를 다시 돌리면 켜진다. 다른 요일 시간표로 대신하지 않는다. 허용 목록이 다른 요일 종류보다 좁은 요일 종류는 manifest의 `lastTrainPartialDays`에 적힌다(지금 `["saturday"]`).

**칸 분포**(82,931칸 = 653 × 127, 대각 127칸 포함).

| 요일 종류 | 열차 | 직행 확정 | 여유(직행) | 여유(환승) | 확인 필요 |
|---|---:|---:|---:|---:|---:|
| 평일 | 3,388 | 4,515 | 3,055 | 73,276 | 2,085 |
| 토요일 | 932 | 4,427 | 0 | 18,659 | 59,845 |
| 휴일 | 2,615 | 4,447 | 3,195 | 73,422 | 1,867 |

검토 전에는 직행 확정이 평일·휴일 112칸(신분당선)뿐이었다. 서울 1~8호선을 자동 대조로 올리면서 4,400칸대가 됐다.

## 2. 발행 게이트와 회귀 검사

`build`는 아래를 모두 통과해야 산출물을 쓴다(`data/config/last-train-report.json`에 결과). `validate`는 다시 계산해 발행된 표·수집일·일부 요일 목록과 대조한다.

| 검사 | 평일 | 토요일 | 휴일 |
|---|---|---|---|
| 번호 가린 채점(서울 1·3~8호선): 쌍 / 일치 / **늦음** / **없는 직행** / 이름 / 빠짐 | 8,169 / 7,960 / **0** / **0** / 136 / 73 | 8,168 / 8,096 / **0** / **0** / 0 / 72 | 8,168 / 8,096 / **0** / **0** / 0 / 72 |
| 여유를 늘려(15분, 3배 + 10분) 다시 계산했을 때 늦어진 칸 | 0 | 0 | 0 |
| 직행이 전체 최선보다 늦거나, 분류와 값이 어긋난 칸 | 0 | 0 | 0 |
| 물리 상한(보인 시각 + 주행시간의 60% − 5분 > 집 역 마지막 도착)을 넘는 칸 | 0 | 0 | 0 |
| 운영사 파일 대조: 우리가 늦은 최댓값 ≤ 원천 여유 180초 | 35초(9호선) | 0 | 120초(9호선) |
| 공식표 표본(분·행선지·**노선**이 모두 같아야 통과) | 95건 모두 일치 (3절) | (평일과 합쳐 95건) | (평일과 합쳐 95건) |
| 상한 표본(보이는 값이 운영사 시각보다 늦지 않음) | — | — | 3건 통과 |

- **번호 가린 채점**: 열차 번호가 있는 서울 노선에서 번호를 가리고 번호 없는 노선과 똑같이 다시 이은 뒤, 역 쌍마다 마지막 직행 출발을 정답과 견준다. 2호선은 뺀다(순환선은 두 방향이 종착 이름을 같이 써서 이 방법으로 잇지 않는다. 번호 없는 노선에 순환선은 없다). 역간·주행 시간은 정답 열차의 중앙값을 썼다. 모호한 이음을 끊으면서 평일 "이름"이 103 → 136쌍으로 늘었다(이른 쪽). 빠짐 72~73쌍은 6호선 응암 순환 구간(한 방향 운행이라 "종착역 쪽 이웃" 판정이 반대로 난다)이고 이른 쪽이다.
- **공식표 표본의 비교 대상**: 표본은 그 칸의 **마지막 직행 열차**(환승이 칸을 이겨도 따로 보관한 값)의 출발 분, 행선지, 노선 묶음과 견준다. 검토가 짚은 구멍(다른 노선의 직행이 같은 분에 떠나면 통과, 환승이 이긴 칸은 행선지가 비어 일치로 침)을 막았다. 직행이 없는 쌍의 표본은 통과하지 못한다.
- **상한 표본**(`data/config/last-train-ceilings.csv`): "이 칸의 보이는 값은 이 시각보다 늦으면 안 된다". 검토가 찾은 휴일 당산 → 가양·마곡나루·김포공항(운영사 급행 E9683, 당산 23:48:30 출발) 세 칸을 23:48 이하로 고정했다. 지금 세 칸의 표 값은 23:47이고(TAGO 쪽 답 23:50:05 − 3분과 운영사 파일 쪽 답 23:48:30은 화면 값이 같아 분이 이른 쪽을 쓴다) 화면은 **23:40**이다.
- **물리 상한**은 거친 검사다. 급행은 그래프(완행 기준) 주행시간의 약 68%로 달리므로 비율을 60%로 잡았다.
- **독립 오라클**: `prototype/last_train.py`가 같은 규칙(chain v2, 원천 여유, 둘째 원천, 확정 판정)을 Python으로 따로 구현한다. 고정 입력(축·노선 그래프·역간·주행 시간·걷는 시간·허용 노선·대조를 통과한 번호 노선)은 파이프라인이 쓴 `build/last-train/problem.json`에서 받고 시간표 줄과 역 이름 대응은 캐시에서 직접 읽는다. 세 요일 종류 248,793칸(시각이 있는 184,996칸 포함)에서 **다른 칸 0**(약 108 s).
- **CI에서 도는 것**: 원자료가 저장소에 없으므로 위 검사는 로컬 `build`·`validate`에서 돈다. CI는 장난감 노선도(`pipeline/src/test/resources/last-train/toy.json`: 급행 통과 줄, 단축 운행, 중간 출발, 끊긴 통과 줄, 직통 경계, 방향별 걷는 시간, 둘째 원천, 평일에만 대조를 통과한 번호 노선)와 추월 반례(`overtake.json`)로 Kotlin 결과와 오라클의 기대 칸을 대조하고, 오라클 테스트(`prototype/test_last_train.py`)가 기대 파일을 다시 만들어 본다.

## 3. 운영사 공식 시간표 대조 (2026-11-20)

### 3.1 서울교통공사 1~8호선: 발행 때마다 자동 대조

- **출처**: 서울교통공사_서울 도시철도 열차운행시각표(S7), <https://www.data.go.kr/data/15098251/fileData.do>. 파일 기준일 2026-09-01, 수정일 2026-09-14, 이용허락범위 제한 없음. 1~9호선 전 구간, 평일(DAY)·토요일(SAT)·휴일(END), 열차코드 포함. 받은 날 2026-11-20(`./gradlew :pipeline:run --args=official-fetch`, 키 없음. 영수증 `source-manifest.json`의 S7).

## 4. 서버와 계약

- **읽기.** `ArtifactLoader`가 세대 3 → 2 → 1 순서로 `manifest.json`과 dataVersion이 같은 첫 세대를 고른다. 읽지 못하는 세대(예: `lastTrainAsOf`가 `2026-02-30`처럼 달력에 없는 날짜)는 건너뛰어 아래 세대로 기동한다. 막차 표는 구분 행렬처럼 기동 뒤 뒤에서 읽고 검사한다. 세대 1·2 데이터, 읽는 중, 검증 실패면 응답에서 `lastTrainBasis`와 `lastTrains`만 빠진다(실패는 한 번만 기록).
- **기다리지 않는다.** 요청은 막차 표를 기다리지 않는다(`BackgroundLastTrains.current()`는 막지 않는다). 표가 준비되기 전의 응답은 막차 키만 빠진다. 검토 전에는 요청마다 최대 2초를 기다렸다.
- **붙이기.** `RecommendationService`가 순위(상위 3)를 정한 **뒤** 카드마다 사람별 칸을 읽어 붙인다. 순위·시간·이유는 그대로다(막차 표가 있는 서버와 없는 서버의 응답이 막차 키만 빼면 글자까지 같음을 테스트한다). 요청한 구분으로 계산하지 못해 평일 낮으로 대신 계산한 응답에는 붙이지 않는다.
- **숨김.** 출발역을 숨긴 참가자의 항목은 `RecommendRequest.viewerId`가 그 참가자일 때만 들어간다. 방 결과는 토큰으로 확인한 본인(`isSelf`)을 넘기고, 미리보기는 토큰 없이 읽으므로 늘 빠진다(운영자 결정: 공개 참가자의 막차는 미리보기에 남기고, 숨긴 참가자는 항목 자체가 없다). `/recommend`에는 숨김이 없다.
- **시각을 내지 않는 경우**(`lastTrainBasis.unavailable`, 모든 항목이 `check`): 요일 종류를 고르지 않음(`day_unknown`: `/recommend`에 `timeSlot` 없음, 방에 약속일 없음), 약속일이 공휴일 목록 밖(`date_out_of_range`), 수집일에서 120일 지남(`stale`, 서울 날짜 기준. 운영자 결정: 시각과 행선지는 빼고 `check`와 이유만 남긴다).
- **v=1 링크.** 서버는 링크 버전을 모른다. 웹이 `v=1` 링크를 읽으면 `ShareState.slotDefaulted`를 달고, 그 상태로 만드는 `/recommend` 요청에서 `timeSlot`을 뺀다(`recommendBody`). 순위는 지금과 같고(평일 낮) 막차는 `day_unknown`으로 온다. 결과 요청과 공유 미리보기(`shared-preview.ts`) 양쪽을 테스트한다. 공유 카드 이미지 주소(`/s/og`)는 v=2로 다시 적어 만들므로 PR 2에서 막차를 카드에 올릴 때 `slotDefaulted`를 같이 넘겨야 한다.

**화면 안내(PR 2)가 쓸 근거.** 서버는 값과 분류만 준다. 문구는 클라이언트가 만든다.

| 안내 | 응답의 근거 |
|---|---|
| 직행 확정 | `lastTrains[].kind = direct` |
| 여유 시각: 갈아타는 길 | `kind = margin`, `transfer = true` |
| 여유 시각: 공식표 대조 전 노선의 직행 | `kind = margin`, `transfer = false` |
| 확인 필요: 요일을 모름 | `lastTrainBasis.unavailable = day_unknown` |
| 확인 필요: 공휴일 목록 밖의 약속일 | `lastTrainBasis.unavailable = date_out_of_range` |
| 확인 필요: 시간표가 120일보다 오래됨 | `lastTrainBasis.unavailable = stale` |
| 확인 필요: 이 요일은 일부 노선만 안내(토요일) | `kind = check`, `lastTrainBasis.partial = true` (**이번에 추가**) |
| 확인 필요: 그 밖(길을 찾지 못함) | `kind = check`, `unavailable`·`partial` 없음 |
| 시간표 기준일 | `lastTrainBasis.asOf` |
| 요일 종류 | `lastTrainBasis.dayType` |
| 타는 시각(운행일의 분) | `lastTrains[].minute` |
| 행선지("광교행") | `lastTrains[].boundFor { stationCode, stationName }` (직행일 때만) |

`partial`만 새로 넣었다. 토요일의 확인 필요가 "길이 없다"가 아니라 "그 노선의 토요일 시간표가 없다"일 수 있다는 것을 알릴 근거가 없었기 때문이다. manifest의 `lastTrainPartialDays`에서 온다. 칸마다 어느 쪽인지는 가르지 않는다(표에 그 구분이 없다): 일부만 계산한 요일 종류의 확인 필요는 모두 "일부 노선만 안내"로 말하는 것이 맞다.

**계약.** `Result.lastTrainBasis`, `Candidate.lastTrains[]`, `PreviewTime.lastTrain`, `RoomPreviewResult/Decided.lastTrainBasis`. 모두 선택 필드라 옛 웹은 무시한다.

**서버 기동**(로컬 맥, AppCDS 없음, 8회씩 번갈아 측정, 기동 시각 기준 ms. 검토 전 측정).

|---|---:|---:|---:|---|
| 세대 2(막차 표 없음) | 137.5 | 167.5 | — | 286.0 (281~292) |
| 세대 3(막차 표 있음) | 137.0 | 164.5 | 163.5 | 286.5 (281~293) |

## 5. 실행

```sh
./gradlew :pipeline:run --args=official-fetch   # 운영사 공식 파일(S7)을 받는다. 키 없음
./gradlew :pipeline:run --args=build       # 캐시 필요(아래). 막차 게이트 실패 시 산출물을 쓰지 않는다
./gradlew :pipeline:run --args=validate    # 막차 표를 다시 계산해 발행된 것과 대조
python3 -B prototype/last_train.py compare build/last-train/problem.json data/raw data/artifacts/dev/lt.bin   # 독립 오라클(약 108초)
python3 -B prototype/last_train.py expect pipeline/src/test/resources/last-train/toy.json                     # 장난감 기대 칸
```

**캐시 전제.** `build`와 `validate`는 이제 아래 캐시를 모두 읽는다. 하나라도 없으면 실패한다(영수증의 해시와도 견준다).

| 캐시 | 받는 법 | 키 |
|---|---|---|
| S1·S3·S4 (`data/raw/kric.xlsx` 등) | `--args=fetch` | 없음 |
| TAGO S6 (`data/raw/tago/`) | `scripts/fetch-tago.sh` | 필요 |
| 서울 S5 역별 시간표 (`data/raw/seoul/`) | `scripts/fetch-seoul.sh` | 필요 |
| 운영사 공식 파일 S7 (`data/raw/seoulmetro-timetable.csv`) | `--args=official-fetch` | 없음 |

전에는 S5 캐시를 배차 재계산(`headways`·`refresh`) 때만 읽었다. 지금은 막차 계산이 S5를 읽으므로 **캐시를 다시 쓰는 평소 `build`에도 S5·S7 캐시가 있어야 한다.** 캐시만 있으면 `build`는 오프라인이고 키가 필요 없다. 분기 재수집(`refresh`: S5를 새로 받고 배차를 다시 계산)과는 다른 일이다: 재수집 때는 S5·S6을 새로 받은 뒤 `official-fetch`로 S7도 같이 새로 받아야 수집일(`lastTrainAsOf`)과 대조가 같은 시점의 것이 된다. S7을 새로 받았는데 운영사가 시간표를 고쳐 S5와 어긋나면 그 노선·요일은 자동으로 여유 시각으로 내려가고 보고서에 남는다.

## 6. 배포

`deploy-server`가 산출물을 발행한 뒤 새 리비전을 올린다. 발행은 해시 파일 → `manifest.v3.json` → `manifest.v2.json` → `manifest.json` 순서다(`scripts/publish-artifacts.sh`). 운영 중인 옛 리비전은 `manifest.v2.json`을 계속 읽으므로 발행 뒤에도 기동한다(되돌리기 포함). 옛 스크립트로 되돌려 v3가 남아도 새 서버는 dataVersion이 다른 v3를 쓰지 않는다.

**배포 스모크**(`scripts/smoke-server.sh` 3c, 후보 리비전에서 돈다): `timeSlot`을 명시한(`weekday-night`) 추천 1건으로 `lastTrainBasis`(요일 종류·수집일)가 오는지, 신분당선 확정 표본(강남에서 광교로: `direct`, 광교행)이 오는지 본다. 막차 표는 기동 뒤에 읽으므로 `lastTrainBasis`가 올 때까지 2초 간격으로 10번까지 다시 묻는다. 수집일에서 120일이 지나 `stale`이면 경고만 내고 통과한다(그때는 시각이 없는 것이 맞다). 워크플로 파일은 고치지 않았다(같은 스크립트를 이미 부른다).

dev 산출물의 dataVersion은 `20261120.2`다(이 PR의 첫 커밋이 `.1`이었다. 둘 다 버킷에 발행한 적 없다).
