## 시간·그래프 정의

**출발역 승강장 대기 포함, 역 출입 시간 제외.** 출발역에서 원하는 승강장에 이미 있다고 놓고
최초 승차의 평균 대기를 지불한다. 도착역은 어느 승강장에 도착해도 목적지로 인정한다.
집→역, 역사 출입구→승강장, 도착 승강장→출구 시간은 포함하지 않는다.
같은 물리역의 출발·도착은 계약대로 0초다.

주행 S3 `mm:ss` + S4 환승 보행 + 승차마다 배차/2를 합산한다.
비용은 `(정수 초, 환승 수)` 사전식이며, 먼저 최소시간을 찾고 시간 동률일 때 최소 환승을 택한다.
`headways.json`은 평시 개발용 **추정**이다(1·2호선 360초, 3~8호선 480초).
공식 배차나 실측 근거가 없는 가정임을 `estimated=true`와 basis에 명시했다.
시간표·방향·시간대·운행일별 배차로 대체할 수 있도록 모델/요일/기준일/노선 값을 분리했다.

- S3의 앞 행→현재 행 시간을 사용하되, 용답의 앞 역은 성수, 도림천은 신도림,
  둔촌동은 강동으로 명시하여 파일상의 직전 행과 잘못 연결하지 않는다.
- 2호선 본선 시청→…→시청을 닫고 성수·신정 지선을 별도 상태로 둔다.
  성수·신도림에서 S4의 동일 노선 보행+다음 열차 대기와 환승1을 지불한다.
- 5호선은 하남/마천 열차 계통을 나눠 방화~강동 공통 구간을 복제한다.
  마천↔하남은 열차를 바꿔 타야 하므로 대기·환승1이 필요하다.
  공통 구간에서 열차 계통만 바꿀 때는 같은 승강장으로 **보행 0초를 가정**, 다음 열차 대기를 적용한다.
  강동→마천 직통은 환승0이며 이 세 조건을 검증 게이트에서도 검사한다.
- 6호선 응암→역촌→불광→독바위→연신내→구산→응암은 **단방향**이다.
  응암~새절 이후는 양방향이다. 응암순환을 역방향 운행으로 복제하지 않는다.
- 그 밖의 S3 주행은 방향 정보가 없으므로 양방향 동일 시간으로 가정한다.
  S4의 방향별 값이 있으면 보존하며, 역방향 기록만 없으면 보행값을 반대 방향에 복사한다
  (까치산 5→2, 같은 노선 지선 환승 등). 열차 대기는 도착 운행계통 기준으로 별도 계산한다.
- 대칭성 차이는 단방향 응암순환, 출발 노선별 대기 차이 및 S4 방향값 차이를 반영한 결과다.
  양방향 동일 모델의 테스트 그래프에서는 대칭이 유지된다.

## 삼각 부등식 게이트 결정

코디네이터 승인에 따라 상태 그래프와 물리역 OD를 구별한다.
물리역 B를 목적지로 한 번 끊으면 B 안에서 승강장을 옮기는 보행이 생략되므로,
물리역 OD에서 `d(A,C) <= d(A,B)+d(B,C)`가 항상 성립하지 않는다.
시간을 줄이거나 환승 보행을 빼서 이를 억지로 맞추지 않았다.

1. 역×운행계통 상태의 모든 최단거리에서 시간·환승 사전식 삼각 부등식 위반 **0**을 강제한다.
2. 물리역 위반 `d(A,C)-d(A,B)-d(B,C)`는 B의 **최대 최단 환승비용 − 최소 최초대기** 이하인지 검사한다.
   최대 최단 환승비용은 B 내부의 보행+대기 간선만으로 모든 승강장 쌍을 연결해 계산한다.
   B 밖으로 열차를 타고 돌아오는 경로는 이 상한 계산에 허용하지 않는다.
3. 상한 초과·B 내부 환승 단절·비정상 시간·후보 미도달·레지스트리 위반이면 산출물을 쓰지 않는다.
   실패한 시도에서는 기존 정상 산출물을 유지한다. 물리역 위반의 수·분포·예시는 보고서에 남긴다.

예: 신내→오금은 태릉입구에서 끊어 계산한 합보다 38초 길며,
태릉입구에서 생략되는 환승 보행 상한도 38초라 허용된다.
자동 테스트는 이 상한보다 **1초 큰** 잘못된 거리와 손상된 상태 거리를 각각 거부한다.

## 수집·레지스트리·후보

`fetch`는 JDK HTTP 클라이언트로 S1 XLSX, S3/S4 CSV를 받는다. HTTP 200뿐 아니라
Content-Type, XLSX 구조/셀 주소, 정확한 헤더, 행 폭·최소 행 수, 시간 필드를 검사한다.
잘못된 seq에서 온 HTML은 octet-stream으로 위장해도 스키마에서 거부한다.
CSV는 UTF-8(엄격 디코딩) 또는 MS949로 읽고 인용부호·빈 셀을 보존한다.
원본 바이트의 SHA-256을 영수증에 남기며 `build`/`validate`도 원본 해시와 스키마를 다시 검사한다.
다운로드 seq는 고정 계약이 아니므로 소스 갱신 시 포털 최신 목록을 확인해야 한다.

S1은 1,099 데이터행이다. `source-dates.json`에서 ISO/8자리/Excel 일련 날짜를 정규화한다.
유효하지 않거나 빈 기준일 **13건**은 null·dateQuarantined=true로 표시해 최신성 근거에서 격리했다.
좌표·소스 ID가 유효한 역의 주행 연결까지 제거하지는 않았다. S1의 혼합 기준일 때문에
이 레지스트리를 전역 최신 운영 목록이라고 주장하지 않는다.

역 코드는 SecureRandom으로 미사용 3자 base32를 발급하고 파일에 보존한다.
기관+원본 노선 ID+역번호를 소스 식별자로 쓰며, 이름 정규화·좌표 850m 이내·원본 환승노선 ID가
함께 맞을 때 물리역을 합친다. 이름만 같은 먼 역이나 환승 근거 없는 신촌 지상/지하는 합치지 않는다.
기존 소스 ID를 우선 사용하며 동일 소스의 이수/총신대입구 중복행도 처리한다.
초안 코드 32개가 물리역 통합에서 퇴역했지만 삭제·재사용하지 않고 deprecated/replacedBy로 보존했다.
내용이 바뀌면 registryVersion을 올리고 `RegistryCompatibility.checkAppendOnly`로 검사한다.

- 당고개는 S1 역번호 0409의 현 이름 불암산으로 정규화한다(공식 고시 보조 근거는 ATTRIBUTION 참조).
- 까치산은 S1에 5호선만 있지만 S3/S4가 2호선 지선을 명시한다. 같은 공사의 5호선 좌표·물리역을
  사용하고 2호선 출처를 별도로 기록한다. 임의 좌표를 만들지 않는다.
- 후보 원본과 구체적 선정 이유는 `candidate-places.csv`, 사람 검토 목록은 `candidate-review.json`이다.
  엄격한 계약의 `candidates.json`에는 추가 필드를 넣지 않고 코드 목록만 쓴다.
  현재 build는 **초안 생성기**이므로 review를 false로 생성한다. 사람이 검토를 시작하면
  review 기록 보존 방식을 먼저 확장해야 한다.

## 실행·검증 및 남은 운영 경계

```sh
./gradlew :pipeline:run --args=fetch
./gradlew :pipeline:run --args=build
./gradlew :pipeline:run --args=validate
./gradlew :pipeline:run --args=all
./gradlew :pipeline:check
./gradlew build
```

`all`은 fetch→build(게이트→writer)→validate 순서다. build는 S7 비교 때문에 네트워크가 필요하며
validate는 로컬 원본+영수증으로 오프라인 재계산한다. shared/schema writer/loader로
레지스트리·후보·BBOD·manifest를 작성하고 해시·축·셀을 다시 대조한다.
validate는 모든 OD를 재계산해 초와 환승이 모두 일치하는지 검사한다.
HEAD의 레지스트리까지 비교하므로 `.git`이 있는 저장소 체크아웃에서 실행해야 한다.
같은 원본 재실행에서 역 코드와 registryVersion은 유지된다.

`og-copy.txt`와 모든 레지스트리 역명의 글자를 합집합·정렬해 `og-glyphs.txt`를 생성한다.
사용자 별칭 같은 임의 문자의 폰트 커버리지는 웹 쪽 fallback 정책이 별도로 필요하다.

mise 제안(공용 mise.toml은 수정하지 않음):

```toml
[tasks."data:fetch"]
run = './gradlew :pipeline:run --args=fetch'
[tasks."data:build"]
run = './gradlew :pipeline:run --args=build'
[tasks."data:validate"]
run = './gradlew :pipeline:run --args=validate'
[tasks."data:all"]
run = './gradlew :pipeline:run --args=all'
```

최종 검증은 파이프라인 8개 테스트·all과 루트 67개 actionable tasks 전체 build 모두 성공했다.
초기 물리역 삼각 부등식 0 게이트는 실패해 산출물 쓰기를 차단했고,
코디네이터가 승인한 상태/상한 검사로 변경한 뒤 재실행해 통과했다.
개발 산출물 경로는 로컬의 가변 `dev/`이며 GCS 발행기·버전 디렉토리의 원자 교체는 이번 범위 밖이다.
실제 발행은 해시 파일명·불변 버전·manifest 포인터 마지막 교체를 별도 구현해야 한다.

1. **사람의 후보 97개 검토**와 6/8분 기본 배차 가정의 승인/보정. 현재 값은 출시용 정확도 보장이 아니다.
2. 서울/TAGO 키 확보 후 범위 밖 구간·시간표·최신 연장역을 연결할 담당/시점.
3. S7 강동→마천 0초 및 총시간/구간시간/대기의 의미를 제공기관에 확인. 그 전에는 S7을 정답/간선 원천으로 쓰지 않는다.
4. 원본 기반 물리역 통합의 사람 검토(좌표 오차·행별 기준일)와 범위 밖 active의 운영 여부 검토.
5. 실제 데이터 발행기의 불변 버전·원자 갱신·이전 버전 보존과 CI의 비교 기준을 배포할 때 확정.
