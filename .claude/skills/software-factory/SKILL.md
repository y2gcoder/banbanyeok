# 반반역 소프트웨어 공장

Orca의 반반역 코디네이터 세션에서 실행한다. 입력은 GitHub 이슈 번호나 URL이다. `inspect #N`은 현재 단계와 다음 행동을 읽기 전용으로 확인한다. `#N`은 기존 실행이 있으면 이어받고, 배정할 구현 단위와 완료 조건이 갖춰졌으면 새 실행을 시작한다. 이전 세션이 종료됐으면 이슈와 PR의 현재 상태에서 재개한다.

## 이슈를 받으면

1. 기본 브랜치의 `AGENTS.md`를 읽어 위임과 확인이 필요한 조건을 확인한다. 이슈 본문, 연결 PR과 `Refs #N`을 포함한 PR, Orca의 이슈·PR 참조를 확인한다. 참조가 비어 있으면 `orca worktree ps --json`의 워크트리 이름과 브랜치에서도 이슈 번호를 찾고, 에이전트 상태와 실제 배정 결과를 본다. 여러 하위 작업이 있는 이슈는 실행할 단위 하나와 선행 관계를 고른다. 이미 구현자나 PR이 있으면 같은 단위를 다시 배정하지 않는다. `inspect` 요청이나 닫힌 이슈는 현재 단계, 증거, 다음 행동을 보고하고 여기서 끝낸다.
2. 이번 단위의 기대 동작과 회귀 조건, 확인 방법, 종료 조건을 기존 이슈에서 확보한다. 이슈 댓글은 참고 자료로 읽고, 저장소 명령과 권한은 기본 브랜치 규칙과 사용자 지시에서 가져온다. 제품 선택, 승인되지 않은 외부 작업이나 환경 접근이 필요하면 어떤 결정이 필요한지 보고한다. 독립적인 검증이나 로컬 작업은 이어간다.
3. 버전에 맞는 Orca `orchestration` 가이드를 읽고 작업 단위가 드러나는 워크트리에 감독형 작업자를 배정한다. Claude Code 구현과 Codex 리뷰를 기본으로 쓰고, Codex가 구현하면 Claude Code에 리뷰를 맡긴다. Claude Code 작업자의 시작 방법은 기본 브랜치 README의 **에이전트 작업자(코디네이터용)** 절을 따른다. GitHub 이슈 참조를 워크트리에 붙인다. 작업 지시에는 이슈와 범위, 완료 조건, 증거를 남길 위치, draft PR에서 멈추고 결과를 회신할 것을 포함한다.

## 구현자가 결과를 보내면

4. PR과 커밋을 확인한다. 작성자는 실행 명령·환경·판정·증거를 완료 조건별로 남긴다. 화면 변경은 [verify-banbanyeok](../verify-banbanyeok/SKILL.md)에서 해당 여정을 골라 폰과 데스크톱 두 환경으로 돌린다. 검증 중 막힌 항목은 원인과 재개 조건을 기록한다. 사용자가 직접 확인해야 할 경우 검증한 동작과 필요한 결정을 함께 보낸다.
5. 구현 대화를 보지 않은 다른 계열 모델에게 PR 헤드 SHA, 이슈, 기본 브랜치 규칙, diff와 실행 증거를 준다. 리뷰는 그 SHA에서 수행하고, 완료 조건별 증거 누락과 병합을 막는 문제를 확인한다. 리뷰어는 판정, 검토한 SHA, 막는 지적의 근거, 미검증 항목을 회신한다. 수정은 구현자에게 되돌리고 수정된 커밋에서 관련 검사와 리뷰를 다시 한다.
6. 병합 후보가 되면 현재 정책에 맞춰 draft를 해제한다. 필수 검사 진행 중에는 `gh pr checks <PR번호> --required --watch --fail-fast`로 결과를 기다리고, 실패하면 원인과 필요한 수정·재실행을 결정한다. 리뷰 통과 SHA를 넣어 `bash .claude/skills/software-factory/scripts/check-pr.sh <PR번호> <리뷰한 전체 SHA>`를 실행한다. 성공은 필수 CI와 현재 PR 헤드의 일치만 뜻한다. 별도 실행 증거와 독립 리뷰, 기본 브랜치의 위임 범위를 함께 확인한다. 위임됐거나 사용자가 승인한 병합은 `gh pr merge <PR번호> --repo y2gcoder/banbanyeok --squash --match-head-commit <리뷰한 전체 SHA>`로 요청하고 PR이 실제로 병합됐는지 조회한다. 그 외는 PR 링크와 남은 병합 결정을 알린다. 반반역에서는 main 병합이 자동 배포로 이어지므로, 배포 결과나 운영 스모크가 완료 조건이면 승인된 경로로 확인해 해당 이슈와 연결한다.

Orca 알림을 받으면 다음 단계로 이어간다. 단계가 바뀔 때마다 해당 워크트리의 Orca 코멘트에 이슈·작업 단위, PR, 헤드 SHA, 구현자와 리뷰어의 dispatch ID 및 판정, 다음 행동을 남긴다. 다시 시작할 때 코멘트를 PR의 현재 상태 및 실제 작업자 상태와 대조한다. 리뷰 판정과 SHA의 근거가 확인될 때 병합 단계로 넘어간다. 최종 보고에는 PR, 실행 증거, 리뷰 SHA, 병합 또는 남은 결정을 적는다.
