# 반반역 검증 지도

이 폴더는 반반역의 사용자 기능을 검증하는 정본이다. 앱을 조작하기 전에 이 색인을 읽고, 맞는 기능 파일을 따라 한다. 기능 파일의 각 여정은 `../journeys/<이름>.mjs`에 있고 `bash .claude/skills/verify-banbanyeok/scripts/verify.sh drive <이름> [phone|desktop]`로 돈다.

## 기본 전제

- `verify.sh launch`로 이 실행 전용 빈 DB, 서버, 웹을 띄웠다. seed가 만든 예시 방 하나만 DB에 있다.
- `verify.sh doctor`가 `FAIL` 없이 끝났다. 포트 주인이 이 실행이고, 데이터 버전이 작업 트리와 같다.
- 데이터는 `data/artifacts/dev`(수도권)다. 역 이름, 순위, 막차 시각은 이 산출물 기준이다. 산출물이 바뀌면 순위·막차 문구도 바뀐다.
- 이 실행이 띄우지 않은 인스턴스(사용자의 `mise run dev`, 운영)는 조작하지 않는다.

## 조작 관례

- 역할과 접근 이름(`getByRole`)으로 찾는다. CSS나 위치로 찾지 않는다. 같은 손잡이를 `web/e2e-real/`이 쓰므로 문구가 바뀌면 거기서 새 이름을 찾는다.
- 첫 화면은 `각자 입력`으로 열린다. 두 사람 이상 출발역을 한꺼번에 넣는 여정은 `tab "모두 입력"`을 누른다.
- 출발역은 `combobox`에 입력하고 `option`을 누른다. 초성(`ㅎㄷㅇㄱ`)도 된다.
- 첫 입력 전에 `gotoHydrated`로 `/api/healthz`(서버 깨우기)를 기다린다.
- 두 번째 사람은 `newPerson()`으로 만든다. 저장소·쿠키가 분리돼 방장 토큰이 섞이지 않는다.
- 방은 만들 때마다 새로 생긴다. 여정은 남이 만든 방에 기대지 않는다.

## 증명과 건너뜀 보고

- 단계마다 동작 직후의 화면과 접근성 트리를 남긴다(`step`).
- 쓰기가 있는 기능은 `db`로 행을 본다. 쓰지 않아야 하는 기능은 전후 행 수가 같은지 본다.
- 바꾼 화면은 `phone`(390×844)과 `desktop`(1280×800) 둘 다 돌린다.
- 보고에는 여정 이름, 화면, 증거 폴더, 통과 여부를 적는다. 막힌 경로는 시도한 명령과 막힌 전제를 적는다. 다른 경로로 통과시킨 것을 그 경로의 검증이라 하지 않는다.

## 기능 파일 형식

각 파일은 H1 제목과 사용자에게 보이는 동작을 설명하는 한 문단으로 시작한다. 그 뒤 H2 넷을 이 순서로 둔다.

1. `Sub-features`는 짧은 ID와 한 줄 설명이다.
2. `How to get to it (user POV)`은 사용자가 들어오는 모든 길이다.
3. `Driving it with verify.sh`는 `Preconditions:`로 시작하고, 사용자 동작마다 손잡이와 보이는 결과를 짝지은 굵은 머리 항목이다.
4. `Gotchas`는 검증을 낭비하거나 무효로 만드는 함정이다.

구현 세부는 넣지 않는다. 사용자 경로, 손잡이, 필요한 상태, 명령, 보이는 증거만 적는다.

## 기능

- [첫 화면 역 검색과 추천 결과](./home-search.md)는 출발역 고르기, 결과, 자세히, 추천 기준 바꾸기를 다룬다.
- [방 만들기와 참여](./room-join.md)는 방장 방 만들기, 링크로 친구 참여, 방장 화면 자동 갱신을 다룬다.
- ['누구 쪽으로' 뽑기](./favor-draw.md)는 뽑기 방 만들기, 사다리, 저장된 당첨자를 다룬다.
- [공유](./share.md)는 결과 링크 복사, 받은 링크 열기, '나는 누구?', 카톡 버튼을 다룬다.
- [막차 안내](./last-train.md)는 1위 요약의 막차 줄과 "집에 가는 막차" 칸을 다룬다.
