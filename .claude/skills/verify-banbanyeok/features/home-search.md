# 홈에서 방장이 입력하고 추천 보기

홈의 각자 입력과 방장이 입력은 모두 방 만들기로 이어진다. 방장이 친구의 출발역까지 넣으면 새 방에서 추천이 바로 보인다. 기존 무상태 결과와 공유 주소도 계속 열린다.

## Sub-features

- `input-tabs` 두 탭을 방향키로 전환하고 각 탭의 입력을 기억한다.
- `filled-create` 내 칸을 골라 방장이 되고, 저장·공개·보관 안내를 읽은 후 방을 만든다.
- `filled-actions` 같은 방에서 결과 기준을 바꾸고, 공유·사다리·만날 역 정하기를 쓴다.
- `restore-legacy` 기존 결과의 다시 입력과 SEO 미리 채우기는 초안을 복원한다.

## How to get to it (user POV)

- `/`는 각자 입력으로 열린다. 친구 몫까지 채우려면 `tab "방장이 입력"`을 고른다.
- `/result?…`의 다시 입력과 `/?o=…` 주소는 방장이 입력 탭의 출발역을 채운다.

## Driving it with verify.sh

Preconditions:

- `verify.sh doctor`를 통과한 뒤 `verify.sh drive home-search phone`과 `verify.sh drive home-search desktop`을 각각 실행한다.

- **탭과 초안.** 방향키로 탭을 옮기고 두 탭에 넣은 값이 보존되는지 본다.
- **저장 전.** 강남과 홍대입구를 고르고 `내 칸 고르기`에서 두 번째 칸을 선택한다. 저장·공개·만료일 안내와 제출 전 DB 방 개수를 확인한다.
- **방 만들기.** 폰에서는 `button "방 만들기"`를 탭하고 데스크톱에서는 클릭한다. `/r/…`의 1위 카드와 DB의 입장 순서, 대신 넣은 칸과 토요일 만료를 확인한다.
- **키보드 저장 경계.** `web/e2e-real/room-explicit-submit.spec.ts`에서 역 드롭다운 Enter 선택, 내 칸·요일·시간대에서 Enter를 눌러도 방이 생기지 않는 동작, 방 만들기 버튼의 Enter 저장을 Chromium·WebKit에서 확인한다.
- **공유·사다리·정하기.** 링크를 친구에게 보내고 방장 기기에서 사다리를 켜고 뽑아 정한다. URL과 DB 방 개수가 그대로인지 확인한다.
- **기존 주소.** 기존 결과에서 다시 입력을 누르고 별명·시간대가 복원되는지 본다. SEO 미리 채우기를 열고 새 방이 생성되지 않았는지 본다.

## Gotchas

- 실서버 여정은 입장 순서와 만료를 DB로 확인한다. 병렬로 같은 DB에 쓰는 다른 여정을 실행하면 전체 방 개수 확인이 실패할 수 있다.
- 약속 구분의 기본값은 서울 시각이다. 만료를 확인할 때는 토요일을 명시적으로 고른다.
