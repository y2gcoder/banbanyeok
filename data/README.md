## 환승역 전수 대조

원인은 기관별 원본의 환승 노선 ID가 서로 다른 namespace여서 `I4108`(코레일)과 `S1102`(서울교통공사) 같은 ID를 직접 비교해도 같은 환승역으로 연결되지 않았던 것이다. 기관 간 물리역 결합에 수도권의 정규화 이름+근접 좌표 규칙을 추가했다. 기존 레지스트리의 모든 코드를 보존하고, 서울교통공사 원본을 가진 기존 코드 → 오래된 addedIn → 코드 사전순으로 정식 코드를 고른다. 이 순서 덕분에 기존 계산 축의 코드가 모두 유지된다. 같은 source key의 원본 ID가 충돌하면 합치지 않고 실패한다.

`data/config/network-rules.json`의 physicalStations가 범위(위도 36.7~38.3, 경도 126.3~128.0), 850m 근접 기준, 구별/동일 역의 예외와 출처, 우선할 source prefix를 소유한다. 범위는 현재 S1의 수도권·연결 광역철도를 덮는 보수적 좌표 창이며 부산 등 전국 동명이역을 자동 병합하지 않는다. 범위 밖에서는 기존 원본 환승 ID의 결합 규칙만 유지한다. 거리는 기존 모델과 같은 평면 근사 `hypot(Δlat×111, Δlng×88)` km이며 실제 보행 거리로 해석하지 않는다.

registryVersion 3→4, 총 코드 984개 유지, active 952→944 / deprecated 32→40. 퇴역한 코드는 deprecatedIn=4와 replacedBy를 기록했다. 옛 이름 aliases는 정식 코드에 합치며 **코드 별칭의 유일한 원천은 stations.json의 replacedBy**다. 별도 별칭 산출물은 없다. 모든 replacedBy 체인 40개가 순환 없이 active 코드에서 끝나는지도 게이트가 검사한다. 폐역 등 replacement 없는 deprecated 자체는 허용하되 다른 코드의 replacement 체인이 거기서 끝나면 실패한다.

**소비자 후속:** 웹 인덱스·서버는 옛 입력 코드를 replacedBy 체인을 따라 active 코드로 해석해야 한다. 이 작업은 코디네이터가 웹/P3 후속으로 배정한다. 이번 PR은 소비자 로직을 수정하지 않는다. 코디네이터 승인으로 기존 생성기를 실행해 `web/src/lib/stations/index.gen.json`만 동기화했다. 데이터 변경 시 이 인덱스 재생성이 필요하며, 파이프라인 build가 이를 자동 수행하게 할지는 결정이 필요하다.

## SEO 사전계산

[seo-hubs.csv](config/seo-hubs.csv)에 약속 출발지로 유용할 상권·대학가·업무·광역철도 환승 거점 30개와 각 선정 이유를 기록했다. **실제 검색/약속 빈도 통계 순위가 아닌 편집 선정**이다. 관측되지 않은 이용량을 인기 수치로 주장하지 않는다. 현재 그래프가 지원하는 서울교통공사 1~8호선 구간 안에서 도심·서북·서남·동북·동남 거점을 분산시켰으며, 동명이역 신촌은 계산 가능한 2호선 역만 고른다.

`build`/`all`이 [seo-pairs.json](artifacts/dev/seo-pairs.json)을 함께 쓴다. 30C2=435쌍, 각 fair 상위 3개(총 1,305개 결과), 원본 UTF-8 **330,303 bytes**(322.6 KiB), gzip(mtime=0) **28,085 bytes**다. 1 MiB 상한보다 작아 쌍 수를 줄이지 않았다. 전체 registry/candidates/od/seo 합계는 777,391 bytes(별도 manifest/glyphs 제외)다.

- a<b인 코드 사전순, 쌍 정렬·중복 없음. times/transfers의 순서는 항상 a,b다.
- 행렬의 정수 초·환승 값을 shared:core의 `rank(mode="fair", toleranceSeconds=0)`에 전달하고 상위 최대 3개를 쓴다. 별도의 웹 순위 구현은 없다.
- 이유는 shared:app-logic의 `ReasonGenerator`가 생성한다. PersonRef에는 사용자 별칭 대신 `역명 출발`을 넣고, 1위는 2위와, 대안은 1위와 비교한다. 개인/시점 정보 없이 역 이름을 기준으로 한 한국어 문장이다. 분 단위 표시는 공유 모듈의 기존 반올림 규칙이다.
- SEO의 dataVersion은 manifest와 같다. 기존 계약의 선택 필드 `manifest.files.seoPages`에 path=`seo-pairs.json`과 SHA-256·bytes를 기록한다. 형식 세대는 1로 유지한다. 역→코드 대체 정보는 SEO에 복제하지 않는다.
- `validate`는 SEO 해시·크기·manifest 버전뿐 아니라 현재 hub 목록/행렬로 순위와 이유를 다시 계산해 JSON 전체를 대조한다. SEO만 변경돼도 새 dataVersion을 발급하며 동일 입력 재실행은 manifest까지 보존한다.

## 재생성 및 검증

```sh
./gradlew :pipeline:check :pipeline:integrationTest
./gradlew :pipeline:run --args=all
```

단위 테스트 31개와 Postgres 통합 1개, ktlint/detekt를 통과했다. 독립 fixture 골든은 fair 순위·개인별 초·집계·정확한 한국어 이유를 검증하고, 실제 435쌍도 재계산 대조한다. 이름/좌표가 같은 기관 간 중복 병합, 코드/addedIn 보존, 우선 코드, 옛 이름, 반복 실행, 신촌 예외, 먼 동명이역, 범위 밖 동명이역, 순환/없는/퇴역 replacement를 검사한다. suppress/baseline·새 버전·빌드 공용 설정 변경은 없다. 루트 ArchitectureTest의 유한 허용 목록 두 곳과 테스트 이름만 코디네이터 승인대로 app-logic을 포함하도록 바꿨다. SEO 이유를 서버와 같은 공유 모듈에서 생성하기 위한 의존성이며, 다른 모듈 경계는 유지한다.

재생성 결과 출발 코드 240개와 후보 코드 97개는 이전과 같다. OD는 registryVersion 헤더 4바이트를 제외한 **모든 바이트가 이전과 동일**하여 원래 소요시간·환승 수를 바꾸지 않았다. 후보 목록은 코드 집합/순서는 같고 registryVersion만 4로 갱신했다. 키 없는 all 성공, 두 번째 실행은 SEO까지 Artifacts unchanged를 확인했다. 실제 키 배차 갱신은 이번 범위 밖이며 실행하지 않았다.

**3단계 적용 규칙**

- **토요일.** 두 노선의 `02` 88개 응답이 모두 비어 있어 [동해선 토요일 대조 계획](../docs/research/busan.md#6-위험미확인)을
  실행할 수 없었습니다. K1 동해선은 평일·휴일 두 가지, K1 부산김해는 통합 요일판입니다.
  토요일 칸은 평일이나 휴일로 대체하지 않고 별도 결정 전까지 끕니다. O2 부산김해 토요일표는
  이용 허락을 확인할 때까지 대조용으로만 씁니다.
- **방향.** 부산김해의 `U`·`D` 응답을 합친 뒤 `endSubwayStationId`로 방향을 정합니다.
  동해선은 `U`가 부전 쪽, `D`가 태화강 쪽으로 일관됐습니다.
- **막차.** TAGO는 시간표 개정일을 제공하지 않습니다. 부산권 막차는 현행 공식표와
  노선·요일·행선지 대조를 통과할 때까지 끕니다.

**K1 대조 재현 방법**

1. 위 수집 명령으로 TAGO 캐시를 채우고 `python3 -B pipeline/busan/sources.py fetch`로
   K1을 받습니다. 동일한 판의 수치를 재현하려면 `source-manifest.json`에 기록된 두 영수증의
   SHA-256이 대조 당시 판과 일치하는지 확인합니다.
2. `pipeline/busan/sources.py`의 `read_cached`와 `timetable.py`의 `parse_k1`으로
   K1을 해석합니다. `L48B1`·`I26K6` 열차에서 마지막 정차역을 행선지로 삼고 그
   정차역의 출발 칸은 제외합니다. TAGO는 `stations/all-p*.json`에서 역·행선지 ID를
   이름으로 바꾸고, `schedule/`에서 `depTime`이 `0`인 도착 전용 행을 뺍니다.
   두 원천의 이름은 `station_name`으로 정규화하고 공백과 이름 끝의 `역`을 뺍니다.
3. 출발 시각의 초를 버리고 00:00~03:59를 같은 운행일의 24:00~27:59로 변환합니다.
   역·행선지·출발 분별 출현 횟수 중 두 원천의 작은 쪽을 합해 일치 건수를 셉니다.
   부산김해는 평일과 일요일·공휴일 각각을 K1 통합 요일판과 비교합니다. 동해선은
   `01`을 K1 평일에, `03`을 K1 휴일 표본에 대응시킵니다. 역·행선지별
   첫차·막차 차이는 TAGO 최솟값·최댓값에서 각각 K1의 같은 값을 뺍니다.

### 부산권 직행 막차 대조 (#180)

```sh
python3 -B pipeline/busan/last_train.py checks   # 사람이 받은 H1·K2가 있을 때만
mkdir -p build
python3 -B pipeline/busan/sources.py network-input > build/busan-network-input.json
./gradlew :pipeline:run -q --args='busan-preview build/busan-network-input.json'
```

운영자 결정(2026-11-26, ADR-0010)대로 운영사 표는 칸마다 대조하는 데만 씁니다.
원문은 커밋하지 않습니다. 사람이 아래 두 파일을 공개 페이지에서 받아
`data/raw/busan-operator/`(Git 추적 제외)에 둡니다. 그다음 운영사 공지에서 그 파일이 가장 새
판인지 확인하고, `data/config/busan-last-train.json`의 `sha256`과 `reviewedOn`을 고칩니다.

- `H1.xlsx`: 부산교통공사 [2026-08-24 시각표 변경 공지](https://www.humetro.busan.kr/homepage/default/board/view.do?board_no=26088C3X3L&conf_no=80&menu_no=1001040101)의
  첨부 `1~4호선 열차운행계획(2026.8월 이후, 홈페이지용).xlsx`(SHA-256 `fa59d934…`).
- `K2.xlsx`: 코레일 [열차운임/시간표](https://www.korail.com/ticket/reserve/train-timeTable)의
  `동해선 전동열차 시각표(2026.9.1.부터)`(SHA-256 `3c29b97a…`).

`checks`는 파일 해시가 설정과 다르면 멈춥니다. 같으면 B1(1~4호선)과 TAGO(동해선)로 계산한
직행과 운영사 표의 직행을 칸마다 견줍니다. 칸은 (요일 종류, 노선, 만날 역 = 부산 후보 27역,
집 역)입니다. 결과는 `data/config/busan-last-train-checks.csv`(원천의 시각·행선지와 판정)와
`source-manifest.json`의 `H1`·`K2` 영수증(파일 해시, 대조 표 해시, 대조한 B1·S6-busan 해시)에
씁니다. 대조 표 해시는 머리줄과 그 표가 맡은 노선의 행만 파일 순서대로 이은 값이라, H1 행이 바뀌어도
K2 영수증은 그대로입니다. 운영사 값은 대조 표에 적지 않습니다.

| 판정 | 뜻 | 화면 |
| --- | --- | --- |
| `agree` | 1~4호선: 도착 분과 행선지가 H1과 같음. 동해선: 출발 초와 행선지가 K2와 같음 | 1~4호선은 여유 시각(분류 3, 도착 분), 동해선은 직행 확정(분류 1) |
| `differs` | 분·초나 행선지가 다름 | 끔 |
| `origin` | 막차가 그 역에서 출발함(시발역 칸, 승차 마감 하한을 모름). 1~4호선은 B1·H1, 동해선은 K2의 첫 정차로 봄 | 끔 |
| `missing`, `ambiguous` | 한쪽에 직행이 없거나, 같은 시각에 타는 열차의 값이 다름 | 끔 |

`busan-preview`의 `lastTrain`은 같은 칸을 Kotlin으로 다시 계산합니다. 영수증이 맞는데 값이
대조 표와 다르면 멈춥니다. 운영사 표마다 아래 중 하나라도 해당하면 그 표가 맡은 노선을
모두 끕니다. 다른 표와 수도권 막차는 그대로입니다.

- 영수증이 없거나, 다른 파일의 영수증이거나, 그 표가 맡은 노선의 대조 행이나 계산 원천(B1·S6-busan)이 바뀌었다.
- `reviewedOn`이 발행 막차 표의 기준일(`lastTrainAsOf`)보다 이르다.
- K2: `reviewedOn`과 TAGO 수집일이 14일 넘게 떨어졌거나, K2 시행일이 TAGO 수집일 뒤다.

또 부산 칸을 합친 권역 막차 표를 메모리에서 만들어 수도권 축으로 되돌린 값이
